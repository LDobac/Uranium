## 정찰·생존 보상 (2026-11-03, AMB-042-16)
사용자 결정(2026-11-03): z·고정 빌드 목표는 쓰지 않는다(정찰에 따라 대응하는 대신 "항상 방어"를 가르치게 되므로). 목표는 봇이 정찰해 상대의 상황·자원을 알고 맞는 전략을 고르는 것이다. 그래서 **정보를 얻는 것**과 **초반에 일꾼을 지키고 늘리는 것**에만 작은 보상을 주고, "맞는 전략을 골랐는지"에는 보상하지 않는다(r_win과 상대 구성 — 042 `rush-s2`의 러시·운영형 혼합 — 에 맡김). 아래 수치는 모두 기본안(미확정)이다 `[SPEC AMBIGUOUS] AMB-042-16`. 게임 시간은 042-R14처럼 24fps로 환산한다(3:00 = 4,320, 4:00 = 5,760, 6:00 = 8,640, 8:00 = 11,520 프레임).

### 정찰 보상 r_scout (033-R9)
- **입력**: 학습 중인 세션이 받은 `RawFrame`(010-R5: 자기 유닛 + 지금 보이는 적·중립 유닛, `GameEnd.final_frame` 포함)과 맵 공개 정보(`StaticMap.start_locations`, 자기 `PlayerInfo.start_tile`)만 쓴다. "봤다" = 그 관측의 `units`에 소유자가 적인 유닛이 있다(030 엔티티의 "보이는 적"과 같은 집합). 기억된 적 건물(030-R2)은 새로 본 것이 아니다. `PrivilegedSummary`, 적 플레이어의 `start_tile`, 시야 밖 정보는 쓰지 않는다(033-R5).
- **항목**: 한 판에 항목마다 한 번. 원값은 기본안(미확정).

  | 항목 | 성립 조건 | 원값 |
  |---|---|---|
  | 적 본진 발견 | 우리 시작 위치가 아닌 맵 시작 위치 중 하나에서 `main_radius_tiles`(기본안 10) 타일 안(타일 중심 사이 거리)에 적 건물이 처음 보임 | 0.3 |
  | 적 건물 종류 | 적 건물 종류(유닛 종류 표 013의 건물, 종족 무관)마다 처음 보임. 변태로 바뀐 종류(해처리 → 레어)도 새 종류. 예: 스포닝 풀, 익스트랙터, 해처리, 레어, 히드라리스크 덴, 스파이어, 크립·성큰·스포어 콜로니 | 종류마다 0.1 |
  | 적 추가 자원 건물 | 서로 다른 적 자원 건물(커맨드 센터·넥서스·해처리·레어·하이브, unit id 기준) 2개 이상을 본 첫 관측(확장 또는 추가 해처리) | 0.1 |
  | 적 일꾼 수 | 한 관측에 적 일꾼(SCV·프로브·드론)이 `workers_min`(기본안 4)기 이상 동시에 보인 첫 관측(일꾼 줄을 봄) | 0.1 |
  | 적 병력 | 일꾼·건물·라바·알(Egg·Lurker Egg·Cocoon)·오버로드가 아닌 적 유닛이 처음 보임 | 0.1 |

- **시간 감쇠**: 성립한 관측의 프레임 f에서 원값 × d(f). d = 1(f ≤ `full_until_s` × 24, 기본안 240 = 4:00), 그 뒤 `zero_at_s` × 24(기본안 480 = 8:00)까지 선형으로 0, 그 뒤 0.
- **상한**: 판당 감쇠 뒤 원값 합 ≤ `cap`(기본안 1.0). 넘는 몫은 자른다. 상한에 닿은 뒤에도 항목 성립은 042 정찰·대응 지표에 기록한다.
- **가중치**: 정책 가중치 = `weight` × (봇 판 1, 모델 상대 판 `vs_model`). 판당 최대 `weight` × `cap` = 0.15, |r_win|의 15%(사용자 제안 범위 0.1~0.2 안). 모델 상대 판을 줄이는 이유(기본안): 주 대상은 봇 저그 상대의 정찰·대응이고, TvT 모델 판(`rush-s2` 30%)에서 싼 항목 모으기로 기울지 않게 한다.
- 보상은 033-R7대로 그 관측 직전 결정에 붙는다. 정찰 유닛을 보내는 행동 자체에는 주지 않는다(정보를 얻었을 때만).

### 생존 보상 r_survive (033-R10)
- **입력**: 자기 유닛만. n = 그 관측의 자기 SCV 수(완성된 것, 탑승 포함, 생산 중 제외).
- **값**: 직전 관측 프레임 f_prev와 이번 관측 f 사이 구간이 창 [`from_s` × 24, `until_s` × 24](3:00~8:00, 사용자 결정)과 겹치는 초 s에 대해 원값 = s ÷ (`until_s` − `from_s`) × min(n ÷ `scv_target`, 1). n은 이번 관측 값, `scv_target` 기본안 20. 창 전체를 SCV `scv_target`기 이상으로 버티면 판당 원값 1이 최대다. 3:00 전과 8:00 뒤는 0. 결정 간격과 상관없이 게임 시간에 비례한다.
- 건물 수·건물 생존·자원·서플라이는 쓰지 않는다. 띄운 건물로 버티는 것에는 보상이 없다(`reports/m6_t1self_stop.md`, 사용자 결정).
- **가중치**: `weight`(기본안 0.1) × (봇 판 1, 모델 상대 판 `vs_model`, 기본안 0 = 봇 판만). 판당 최대 0.1.
- **봇 판만인 이유(기본안)**: 1차 T1·셀프 run은 모델 상대 판에서 "일꾼·터렛·확장, 병력 거의 없음"으로 무너졌다. 그 판에 일꾼 수 보상을 주면 같은 방향을 민다. 봇 판에서는 러시에 지는 판에도 버틴 시간만큼 신호가 생기고(지금은 r_win −1뿐), 운영형 상대에게는 일꾼 생산을 민다. 붕괴 항복(042-R14)으로 끝난 판은 그 뒤 보상이 없다.

### 보상 채널 모드 (033-R11)
RL 설정 `[reward] pseudo = "z"`(기본, 지금 동작) | `"scout"`. 다른 값은 설정 로드 오류다. value head는 4개 그대로이고(032 §2.6, 구조 변경 없음), 모드에 따라 build·units 채널이 배우는 보상이 바뀐다(2026-11-03 사용자 결정: z를 쓰지 않아 놀고 있는 두 채널을 재사용).

| 채널(value head) | `"z"`: 보상 · 정책 가중치 | `"scout"`: 보상 · 정책 가중치 |
|---|---|---|
| win | r_win · `config/reward.toml` `win` | 같음 |
| build | r_build(z 있는 판만) · `build`(C2 감쇠, 042) | r_scout · `[reward.scout] weight` × 판별 배수 |
| units | r_units(z 있는 판만) · `units`(C2 감쇠) | r_survive · `[reward.survive] weight` × 판별 배수 |
| value | r_value · `value`(042 단계·판별 규칙) | 같음 |

- `"scout"`에서는 z를 쓰지 않는다. `--z-table`을 함께 주면 시작 오류다. 한 head가 판마다 다른 목표를 배우지 않게 둘을 함께 쓰는 구성은 금지한다(메인 임시 결정, 사용자 결정 "z는 쓰지 않음"과 맞음). `"z"`의 뜻은 지금 그대로다.
- 판별 배수(`vs_model`)는 r_value(042 "r_value의 게임별 적용")처럼 세그먼트(판) 단위로 V-trace PG·UPGO에 적용한다. value 손실은 배수와 상관없이 모든 판에서 원값 목표를 학습한다.
- 모드는 체크포인트의 RL 설정에 기록한다. 재개할 때 지금 설정의 모드가 체크포인트와 다르면 시작 오류다(head의 뜻이 바뀐다, 메인 임시 결정). `--init` 새 run은 출발 체크포인트의 모드와 상관없다(z 없이 학습한 체크포인트의 build·units head는 목표 0을 배운 상태).
- C2의 pseudo-reward 감쇠(042 커리큘럼)는 `"z"`에만 적용한다. `"scout"`의 C2 처리는 C2 진입 전에 다시 묻는다(메인 임시 결정).
- 로그: `games.csv`의 `r_build`·`r_units`는 이름대로 z 보상이다(`"scout"`에서는 0). 새 열 `r_scout`·`r_survive`에 원값 합을 쓴다(`"z"`에서는 빈 값, 042-R2). 채널 위치는 내부 표현이고 로그 이름은 보상 이름을 따른다(메인 임시 결정).
- 설정 키(메인 임시 결정): `[reward.scout]` `weight`·`cap`·`vs_model`·`full_until_s`·`zero_at_s`·`main_radius_tiles`·`workers_min`·`main`·`building_type`·`expansion`·`workers`·`army`, `[reward.survive]` `weight`·`vs_model`·`from_s`·`until_s`·`scv_target`. 검사: 가중치·원값·`cap` ≥ 0, `vs_model` 0~1, `full_until_s` ≤ `zero_at_s`, `from_s` < `until_s`, `scv_target`·`workers_min`·`main_radius_tiles` ≥ 1. 벗어나면 설정 로드 오류다. 재개 때는 지금 설정 파일 값을 쓴다(042 "재개 시 설정").

| 033-R7 | **MUST** RL에서 한 결정(agent step)의 보상은 그 결정 뒤 받은 프레임들의 보상 합이다. 종료 보상 r_win은 마지막 결정에 더한다 (2026-10-17). 마지막 결정 뒤 게임 종료까지의 프레임 보상은 브리지가 `GameEnd.final_frame`(010-R12)으로 보낸 최종 관측으로 계산해 마지막 결정에 더한다(E-8, 사용자 결정 2026-10-19) |
| 033-R8 | **MUST** RL의 z는 shard에서 미리 계산한 z 테이블(`uranium-train z-table`, 대상 맵·테란 시점 게임의 `replay_z`)에서 뽑는다. z 테이블이 없으면(본 shard 이전) 모든 게임을 z 없이 진행하고 그 사실을 로그에 남긴다. 이때 pseudo-reward는 꺼지므로 033-AC2는 z 테이블이 생긴 뒤에만 의미가 있다 (2026-10-17) |

## Acceptance Criteria
- 033-AC1: 보상 함수 단위 테스트를 통과한다. 합성 시나리오에서 부호와 크기가 맞는지 확인한다.
- 033-AC2: pseudo-reward를 끈 ablation과 승률 곡선을 비교해 [042](042-rl-training.md)에 기록한다. 조건은 042-AC1과 같다: 투혼, T0 1종족, seed당 300만 agent step(042-AC1을 따름, 2026-11-01), 3 seed(2026-10-17 개정, 이전 "초기 1M 스텝"은 KL 반감기 대비 너무 짧음).
- 033-AC3 (2026-11-03, 033-R9~R11): 단위 테스트 — r_scout: 항목마다 한 번(같은 종류·같은 건물 재목격은 0), 변태한 종류는 새 종류, 기억된 적 건물은 목격 아님, 적 `start_tile`·privileged에만 있고 보지 못한 적은 0, 본진 반경 경계, 일꾼 `workers_min` 경계, 감쇠 경계(5,760 프레임 그대로, 11,520 이후 0, 중간 선형), 판당 `cap` 자름. r_survive: 창 경계(4,320 전 0, 11,520 뒤 0, 창에 걸친 구간은 겹친 초만), 생산 중 SCV 제외, 건물만 남으면 0, `scv_target` 자름, 같은 관측 열을 결정 간격만 달리 나눠도 합이 같음. 채널 모드: `"scout"`에서 build·units 채널에 두 보상, `vs_model` 배수는 세그먼트 단위로 PG·UPGO에만, `"scout"` + `--z-table` 시작 오류, 재개 때 모드 변경 시작 오류, 설정 값 검사.

## Risks & Open Questions
- **정찰·생존 보상(2026-11-03, AMB-042-16)**: ① 적 병력 항목은 러시 상대가 우리 본진에 오면 저절로 성립한다(판마다 거의 같은 작은 상수, 정책 신호는 거의 없음). ② r_survive는 SCV를 잃으면 줄어 일꾼 동원 방어를 약하게 벌한다. 크기는 SCV 2기를 60초 잃을 때 가중치 뒤 약 0.002로 r_win·r_value보다 훨씬 작다. ③ 두 보상 모두 정책 가중치 상한이 판당 0.15·0.1이라 승패를 뒤집지 않는다. 효과가 없거나 부작용이 보이면 042 점검 지표(정찰·대응)로 판단해 사용자에게 보고한다.
