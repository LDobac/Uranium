## Purpose
같은 게임 상태에서 우리 행동만 바꿔 이어 둔 판(분기 게임)들의 결과 차이로 **행동의 인과 효과**를 잰다. 기록된 판만으로는 "벙커 때문에 졌다"와 "벙커를 지을 상황이라 졌다"를 가를 수 없었다(S0b M3b, `reports/jepa_planning.md` 7.1). 분기 게임은 교란 없는 정답을 주므로 다음에 쓴다.
- S0 예측기(채점기 q̂, 내 상태 변화 ô)를 교란 없이 평가한다(M3u, M2c).
- 러시 대응(벙커 등)과 운영 행동의 실제 효과 크기를 잰다.

방법은 **강제 재생**이다(`reports/jepa_planning.md` 7.3 (가)). 줄기 판(trunk)을 평소처럼 두며 관측마다 보낸 `Act`와 모델 상태를 기록하고, 분기 판(branch)은 같은 seed·맵·상대로 새로 시작해 줄기의 `Act`를 결정 시점 t까지 그대로 보낸다. t에서 저장한 모델 상태를 되살리고, 행동 종류 마스크로 대안을 넣은 뒤 정한 시간까지 모델이 실제로 둔다.

## Scope & Non-goals
- **범위**: OpenBW lockstep 게임, 우리 모델(테란, `players[0]`, stochastic) 대 T0 스크립트 봇(`players[1]`), 맵 투혼·서킷브레이커. 줄기 기록, 분기 플레이어, 분기 plan·결과 기록, 분석(M3u·M2c·짝 효과 추정).
- **첫 묶음 B1**(러시 대응): T0 `zerg_rush` 상대, 결과 범위 8:00. **B2**(일반 운영 행동, 12:00)는 B1 결과를 본 뒤 정한다(AMB-051-6).
- **Non-goals**
  - OSS(T1) 상대. 시각·난수 seed·경과 시간을 써서 앞부분이 재현되지 않는다. AMB-021-3("패치하지 않음")은 그대로 둔다(사용자 결정 2026-11-12).
  - 판 끝까지 두기(승패). 정한 시간까지만 둔다(사용자 결정 2026-11-12).
  - 엔진 스냅샷 복원(BWAPI `saveSnapshot`·`loadSnapshot`), 리플레이 이어받기(`reports/jepa_planning.md` 7.3 (나)·(다)).
  - 교사(021-R8)에게 일정 시간 맡기는 대안. 마스크가 아닌 다른 정책 경로가 필요해 이번 범위에서 뺀다.
  - 분기 데이터로 채점기를 학습하는 일(분석에서 평가만 한다. 학습은 계획 모듈 spec에서 따로 정한다).
  - SC:R(realtime) 게임. 강제 재생은 lockstep에서만 성립한다(001-R5).
  - 계보 측정(050-R9)·승격 게이트(050-R3)에 분기 판을 넣는 일.

## 용어
| 용어 | 뜻 |
|---|---|
| 줄기 판(trunk) | 분기의 원본이 되는 판. 평소처럼 두며 051-R2·R3 기록을 남긴다 |
| 결정 시점 t | 줄기 판 모델 세션의 한 결정(관측 번호 i_t, 프레임 f_t). 그 결정 직전의 모델 상태가 저장돼 있어야 한다 |
| 분기 판(branch) | 줄기와 같은 seed·맵·상대로 시작해 t 전까지 줄기의 `Act`를 강제하고, t에서 대안을 넣어 이어 둔 판 |
| 대안(alternative) | t와 그 뒤에 적용하는 마스크 규칙 목록(051-R7). 규칙이 없으면 "개입 없음"(`none`) |
| 반복(repeat) | 같은 (t, 대안)을 다시 둔 판. t 뒤 모델 뽑기만 다르다 |
| 관측 다이제스트 | 관측 하나(`RawFrame`)의 postcard 인코딩 바이트에 대한 FNV-1a 64비트 값(051-R2) |
| 호라이즌 H | 분기 판을 끝내는 게임 시각. B1 8:00(11,520프레임), B2 12:00(17,280프레임) |

## Acceptance Criteria
- 051-AC1 (CPU 단위 테스트, Rust): 행동 기록 줄 쓰기·읽기 왕복(010 `Command` 모든 종류의 인자 포함), 관측 다이제스트가 관측마다 새로 시작하고 세션 `frame_digest`와 같은 바이트를 먹음, 끝 줄 없는 기록 거부. snapshot 규칙: 창 경계(시작 포함·끝 제외), `any_open`, 창마다 첫 결정 하나, 두 규칙이 같은 결정에 걸릴 때 파일 하나. 상태 파일 왕복 비트 일치·sha256. 개입: `force`가 첫 열린 결정 하나만 {action}으로 좁힘, 창 안에서 끝내 안 열리면 `missed`, `ban` 창 경계, 닫힌 비트를 열지 않음, NoOp은 `ban`으로 닫히지 않음, `unit_cap`·`loc_class_mask` 불변, 좁힌 마스크로 executor가 같은 명령을 냄(031-R7). 강제 앞부분: 합성 관측열에서 프레임·다이제스트 불일치 → 무효와 빈 채팅 퇴장 `Act`, 일치 → 기록된 `Act` 바이트 그대로, 기억이 줄기 세션의 기억과 같음(같은 관측열을 평소 경로로 흘린 기억과 비교). plan: `branches` 줄 수·seed·맵·상대 불일치 로드 오류, 키 없는 기존 plan 결과 불변. plan 생성 도구: 같은 입력 같은 출력, 051-R10의 거부 사유마다 시험.
- 051-AC2 (CPU 단위 테스트, pytest): `set_state` 왕복 비트 일치, 되살린 슬롯의 `act` 출력이 되살리지 않고 같은 관측을 거쳐 온 슬롯과 비트 일치(LSTM·GTrXL K/V 캐시 두 구성), 같은 배치의 다른 슬롯 불변, 모양 불일치 오류, 처리 순서(리셋 → 되살리기 → 상태 읽기 → act).
- 051-AC3 (결정론, hostd 필요한 무시 테스트): `crates/uranium-scripted/tests/branch_replay.rs`를 051-R2 행동 기록 형식과 051-R5 강제 경로로 옮긴다. T0 테란 줄기 대 T0 저그 러시, 강제 판에서 두 플레이어의 모든 관측 다이제스트가 줄기와 같고(불일치 0), 분기 판은 t 전 관측이 모두 같고 t 뒤 첫 관측부터 다르다.
- 051-AC4 (그림자 확인): 051-AC3 강제 판에서 그림자로 돈 T0 테란의 `Act`가 모든 강제 관측에서 기록과 같다(불일치 0). 모델: 051-AC6의 `verify_state` 분기에서 앞부분 추론으로 쌓은 상태가 t에서 저장 상태와 같다(CPU 추론. 비트 일치를 기대하되, 줄기와 배치 구성이 달라 생기는 차이는 032-R14 배치 허용 오차까지 허용하고 어느 쪽인지 기록).
- 051-AC5 (분기 뒤 갈라짐): 051-AC6에서 t의 결정이 줄기와 다른 분기(`force` 대안)는 우리·상대 모두 t 전 관측이 줄기와 같고, 상대의 첫 다른 관측이 t 뒤다.
- 051-AC6 (작은 end-to-end, Linux CPU 호스트, CPU 추론): B1 규칙으로 줄기 2판(맵마다 1판, 호라이즌 8:00) → plan 생성 → 시점마다 대안 `none`·`force Build_Bunker` × 반복 1, 첫 분기 판 둘은 `verify_state = true`. 모든 분기가 유효하고, 051-AC4·AC5가 성립하며, `points.jsonl`·`branches.jsonl` 필드가 모두 차고, 분석 명령이 끝까지 돌아 표를 만든다(수치는 판정하지 않음). 시작 전에 CPU 추론 속도를 판 하나로 재고, 2시간을 넘을 것 같으면 호라이즌을 4:00으로 줄여 사용자에게 보고한다.
- 051-AC7 (B1 실행): B1 판을 끝까지 돌리고 무효 분기 수·사유, 대안별 거절·`missed` 비율, 051-R13 표를 `reports/branch_b1.md`에 낸다. 무효 분기가 1%를 넘으면 원인을 먼저 보고한다.

## Risks & Open Questions
- **빌드 불일치**: T0 봇은 우리 에이전트 프로세스 안에서 돈다. 줄기와 분기의 에이전트·hostd(OpenBW·브리지) 빌드가 다르면 앞부분이 갈라질 수 있다. 정책 버전·git 커밋을 기록하고 plan 생성 때 확인하며, 다이제스트 확인이 최종 방어선이다.
- **리플레이 바이트**: BWAPI `Unitset` 순서 때문에 같은 판의 리플레이 바이트가 다를 수 있다(`reports/jepa_planning.md` 7.9). 일치 확인은 관측 다이제스트로만 한다.
- **한 결정 효과의 희석·executor 거절·T0 한정·분포·뽑기 재현 불가**: `reports/jepa_planning.md` 7.11 표 그대로. 희석·거절은 051-R9 ③·R7 ⑤로 기록한다.
- **상태 파일 크기**: GTrXL 층 입력 기준 하나에 1 MB 안팎으로 추정(측정 안 함, TBD(B1)). B1 80개는 문제 없다.
- **ROCm 비결정성**: 줄기를 ROCm에서 두면 t 시점 상태는 그 판의 실제 상태 그대로 저장되므로 되살리기가 재현 문제를 비켜 간다. 분기 판 이어 두기의 추론 호스트는 줄기와 달라도 되며(f32 가중치, 032-R8) 기록만 한다.
- **분석 입력의 근사**: h'_t는 라이브 관측이 아니라 리플레이 재생 관측(프레임 f_t − 2, 041-R28 ②)에서 CPU로 덤프한다. S0 예측기가 같은 방식의 데이터로 학습됐으므로 맞춘 선택이다.
