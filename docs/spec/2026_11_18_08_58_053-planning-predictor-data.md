## Purpose
S0b 예측기는 행동을 거의 무시하고 결과 머리는 판을 외웠다([B1](../report/experiment/2026_11_18_01_10_branch_b1.md) M3u, [점검](../report/investigation/2026_11_18_08_58_jepa_predictor_data.md)). 원인인 데이터 구성·결과 정답·학습 절차를 고치고, 모델이 둔 판과 개입 데이터(분기·탐색)로 행동 효과를 배우는 예측기를 만든다.

## Scope & Non-goals
- **범위**: `diag plan-dump`·`plan-s0`·`plan-branch`(`python/uranium/diag/planning/`)의 데이터·정답·학습·평가, 모델 판 리플레이 build(041-R28 기억 기록).

  | 단계 | 내용 | 요구사항 |
  |---|---|---|
  | 1 | 결과 정답, 출처 섞기, 검증·조기 멈춤(기존 S0b 출처) | R1~R4 |
  | 2 | 모델이 둔 판 출처 추가, 큰 데이터 로더 | R5·R6 |
  | 3 | 예측기마다 B1 재확인 | R7 |
  | 4 | 탐색 판(054)·B2(051) 데이터로 학습 | R8 |
- **Non-goals**
  - 모델(032) 구조·BC·RL 손실 변경. 예측기는 고정 체크포인트의 h' 위에 따로 학습한다.
  - 계획 모듈(예측기로 행동 고르기)·실전 사용. 이 spec은 예측기까지다.
  - 측정 리플레이(기억 기록 없음)·RL fix-2 판(리플레이 표본 16개, 기억·log-prob 없음) 사용.
  - 판정 문턱. 결과는 보고만 하고 다음 단계는 사용자가 정한다(051-R13 ⑦과 같음).

## 용어
| 용어 | 뜻 |
|---|---|
| C | 덤프 체크포인트. 모든 출처의 h'·π를 이 하나로 뽑는다 |
| F | 교사 모드 누출 수정의 최종 가중치(044-R13 ⑤: RL 끝 또는 t2) |

| 명령 행 | 리플레이 명령 레이블 행(재생 약 L + 2). 기억에 결정 L이 이미 들어 있다 |
| 세계 머리 / 결과 머리 | ŷ·p̂·ô / q̂(결과 확률) |

## Acceptance Criteria
- 053-AC1 (CPU pytest) 결과 정답: 합성 `results.jsonl`로 판 id 재시도 마지막 줄, sha256 잇기, 정의 4개(8:00 전 끝 승·패, 무승부 → 없음), 잇지 못함 → 없음(0 아님), coverage 수.
- 053-AC2 (CPU pytest) 옛 설정 재현: 섞기·검증·결과 머리 플래그를 모두 끈 학습이 S0b 코드와 모델·표 비트 단위로 같다. 섞기를 켜면 실현 몫이 목표 ±1%p 안(합성 데이터).
- 053-AC3 (CPU pytest) 검증: 학습·검증·평가 판이 겹치지 않음, 두 관점 같은 쪽, 남긴 가중치 = 최저 검증 step, 세계·결과 망 분리, 보고 지표가 평가 판만.
- 053-AC4 (사전 점검, 보고) 정답 coverage: 기존 S0b 출처와 R5 출처 모두 머리별 coverage 표.
- 053-AC5 (사전 점검, 보고) 행동 섞기 대조: 출처 안에서 행동을 섞어 학습한 예측기와 R3·R4 예측기의 운영 행동 행 내 상태 변화 오차·후보 간 결과 폭 비교.
- 053-AC6 (사전 점검, 보고) 누출 탐침: B1 줄기 덤프에서 h'로 기록된 결정 종류를 맞히는 탐침의 정확도를 명령 행과 결정 행에서 따로 낸다.
- 053-AC7 (사전 점검, 보고) 결정 행 정책 확률: C가 둔 판(B1 줄기 등)에서 결정 행·명령 행의 π(기록된 결정) 분포.
- 053-AC8 (사전 점검, 보고) 라이브 대 재생 π: 라이브 `type_logp`가 있는 판(054-AC4 20판, B2 줄기 `policy_top`)에서 라이브 π와 덤프 π(L − 2 행)의 평균·최대 차, top-1 일치율.
- 053-AC9 (사전 점검) build 표본: R5 출처마다 리플레이 5개를 build·덤프해 `players[0]` 관점만, 10:00 절단, 기록된 결정마다 결정 행이 L − 2에 있음, 기억 기록 없는 판 거부.
- 053-AC10 (규모) 1,000만 행(합성 가능)을 R6 로더로 학습 1,000 step, 최대 RSS 보고, 예산 안.
- 053-AC11 (단계 3) R7 표를 리포트로 낸다(예측기마다 M3u·M2c, S0b 나란히).
- 053-AC12 (CPU pytest, 단계 4) 탐색 행 가중치 상한 10, 떼어 둔 B2 줄기·탐색 판·B1 행이 학습 배치에 없음, 짝 손실이 같은 시점 대안끼리만.

## Risks & Open Questions
- **F 교체**: F가 gn과 다르면 모든 덤프·학습을 다시 한다(덤프 Linux ROCm 약 400행/초, CPU 약 28행/초 — [점검](../report/investigation/2026_11_18_08_58_jepa_predictor_data.md) 7절).
- **결정 행 근사**: L − 2 재생 관측은 라이브 관측과 같지 않다(051 위험 절과 같음). AC8로 크기를 잰다.
- **propensity 범위**: C가 두지 않은 판은 π가 없어 개입 보정이 안 된다. 개입 보정은 탐색 행(054)만.
- **드문 행동 배율**: ×20은 외우기를 키울 수 있다. 검증(R4)이 막는지 본다.
- **사람 몫**: 0%·20%·35% 비교 결과로 사용자가 정한다.
