# 공간 인코더 GroupNorm 재개 시험 (`m2-gn-t1`)

spec [032](../../spec/2026_10_15_22_24_032-model-architecture.md) §2.8 `spatial_norm`(032-R26)을 켜고 Checkpoint 2에서 BC를 이어 학습해, 죽은 공간 채널이 살아나는지 본다.

## 1. 배경과 예상 (실험 전, 2026-11-17 10:0x 작성)

### 배경
- 공간 인코더는 ResNet 꼴이지만 정규화 층이 없다. 끝 ReLU를 뺀 모델 2(032-R22)에서도 깊은 단계 채널 대부분이 죽어 있다([model2](../plan/2026_11_09_22_18_model2.md) 9.7절).
- 사용자 결정(2026-11-17): GroupNorm을 pre-activation ResNet 위치에 넣고, Checkpoint 2(`m2-teacher-t1/ckpt-2844`)에서 BC 3,000 update를 이어 학습해 확인한다.

### 설정
| 항목 | 값 |
|---|---|
| 설정 파일 | `config/bc_m2_gn_t1.toml` |
| 출발 | `m2-teacher-t1/ckpt-2844` 가중치만(`--init`), GroupNorm은 scale 1·bias 0 |
| GroupNorm | 13개 층, 그룹당 16채널(그룹 수 2/4/4/8/8), 파라미터 2,624개 |
| 학습 | Checkpoint 2 학습과 같은 데이터·seed·학습률(3e-5), 3,000 update, warmup 150 |
| 장비 | Windows CUDA 호스트(bf16 혼합) |

### 비교 기준 (Checkpoint 2 학습 로그 `<shared>/eval/m2-lineage/train_logs/m2-teacher-t1.log`)
죽은 채널 수(마지막 10회 기록 평균, 100 update마다 한 batch, [041-R25](../../spec/2026_10_15_22_24_041-imitation-learning.md)):

| 층 | 채널 | 죽은 채널 평균 | 전체 최대 | 양수 비율 |
|---|---|---|---|---|
| 다운샘플 conv 3번째(c2) | 64 | 25.4 | 37 | 0.044 |
| 다운샘플 conv 4번째(c3) | 128 | 80.9 | 100 | 0.007 |
| bottleneck 1번째 안(r4) | 128 | 84.9 | 94 | 0.023 |
| bottleneck 2번째 안(r5) | 128 | 90.7 | 94 | 0.048 |
| 다운샘플 블록 안(r0~r3) | 64~128 | 0.1~9.2 | 13 | 0.11~0.16 |

- `S8`·`s_pool` 상수 채널 0. 전체 손실 마지막 200 update 평균 7.62(행동 0.685).

### 예상
- 재개 직후: GroupNorm이 ReLU 앞 값을 그룹 안에서 0 중심으로 되돌리므로 죽은 채널 수는 바로 크게 준다(무작위 입력 확인에서 c3 117 → 0, r4 103 → 0).
- 손실: 함수가 바뀌어 처음에 오르고 수백 update 안에 Checkpoint 2 수준 근처로 돌아온다. 처음 2,844 update는 Checkpoint 2 학습과 같은 데이터 순서라 이미 본 데이터이므로, 손실이 Checkpoint 2 기록보다 낮아도 개선 근거는 아니다.
- 3,000 update 끝: 죽은 채널이 낮게 유지된다. 다시 늘면 정규화만으로는 부족하다는 뜻이다.
- 이 시험이 말해 주지 않는 것: 살아난 채널이 쓸모 있는 정보를 담는지, 게임 실력. 단서 진단([050-R9](../../spec/2026_10_15_22_24_050-evaluation.md))과 게임 측정은 하지 않는다.

### 두 번째 시험: 끝 ReLU 추가 (`m2-gn-relu-t1`, 2026-11-17 11시대 작성, 시작 전)
- 사용자 결정(2026-11-17): 같은 GroupNorm 구조에 블록 끝 ReLU만 다시 넣어 한 번 더 본다([032-R27](../../spec/2026_10_15_22_24_032-model-architecture.md), `spatial_end_relu`).
- 설정 `config/bc_m2_gn_relu_t1.toml`: 첫 시험과 다른 점은 `spatial_end_relu = true` 하나. 출발·데이터·seed·학습률·길이 같음.
- 첫 시험 중간 관찰(update 1,200까지): c3·r4 죽은 채널 0, r5 1, 세 번째 다운샘플 단계 블록 출력(d2) 128채널 중 16~29개가 항상 0 이하.
- 예상:
  - Checkpoint 2는 블록 출력이 음수일 수 있다는 전제로 학습됐으므로 재개 직후 손실 상승이 첫 시험보다 크다.
  - 블록 안 ReLU(c·r 층)는 GroupNorm 뒤라 첫 시험처럼 살아 있다.
  - 블록 출력(d·b 열)에 죽은 채널이 생긴다. 특히 d2는 첫 시험에서 항상 0 이하이던 채널 수(16~29) 근처에서 시작한다. 학습으로 줄면 끝 ReLU가 해롭지 않다는 쪽, 늘거나 `S8`·`s_pool` 상수 채널이 생기면 Checkpoint 1과 같은 붕괴 쪽이다.
  - 블록 출력은 경보 규칙([041-R25](../../spec/2026_10_15_22_24_041-imitation-learning.md)) 대상이 아니라 로그 열을 직접 읽는다.
