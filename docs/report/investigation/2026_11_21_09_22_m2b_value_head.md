## 1. 손실 정의 (코드 확인)

| 항목 | 값 | 위치 |
|---|---|---|
| value 출력 | `tanh(out[0])`, 입력 Core 출력 h·z·종족·privileged 요약 | `python/uranium/model/value.py` |
| win_open 출력 | `tanh`, 별도 MLP, 입력 **h.detach()**·z·종족(privileged 없음, Core로 기울기 안 감) | 같은 파일 |
| 정답 | 판 결과 ±1(테란 시점), 결과 없는 판은 가중치 0 | [041](../../spec/2026_10_15_22_24_041-imitation-learning.md)-R7·R19, `crates/uranium-data` `value_weight` |
| 손실 | 가중 MSE, 가중치 value 0.5·win_open 0.5 | `python/uranium/bc/trainer.py` `group_loss` |
| clip | value는 전역 L2 clip 1.0에 포함, win_open 파라미터는 따로 clip | `python/uranium/clip.py` |

- 상수 c 예측 MSE = 1 − 2cm + c²(m = 정답 평균). 0 예측이면 1.0, 최적 상수면 1 − m²(이 val 0.998).
- 처음 값 약 0.98·최근 B 0.92~0.94(update 17,69x)가 상수 수준. 0.69는 상수 수준이 아니라 그 사이. 1을 넘으면 자신 있게 틀린 것.

## 4. 평가 중 장비 응답 없음 (확인)

- 09:13쯤 Linux ROCm 호스트(1호기)가 SSH에 응답하지 않음(ping은 응답, 22번 포트 연결 시간 초과). 원래 1.5만 체크포인트 평가 프로세스를 띄운 직후.
- 그 전 메모리 상태: 한 프로세스에서 여러 체크포인트를 차례로 돌리면 프로세스 RSS가 11~12 GB까지 차고 사용 가능 메모리가 1.1~1.7 GB까지 내려감(가드 1 GB가 두 번 종료시킴). 체크포인트마다 프로세스를 나눈 뒤에도 B 평가 중 RSS 약 8.7 GB·사용 가능 약 4.5 GB. GTT 1.6~1.8 GB. RSS 대부분은 데이터 스트림 쪽(4판 시험 5.6 GB, 레인 32→8로 줄여도 비슷).
- 재발 방지(기본안(미확정), 결정은 사용자): 그 장비에서 평가 메모리 가드는 사용 가능 4 GiB 이상, 한 체크포인트 한 프로세스.
- 남긴 것: 별도 사본 `<repo>/local/work/m2b_value_diag/`(코드 사본 `repo/`, 평가 출력 `out/`, 시험 `pilot/`). 장비가 돌아오면 남은 평가 프로세스를 끝내고 `repo/`를 지운다.
