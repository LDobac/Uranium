# 보조 예측기와 Adam eps 조사 (2026-11-18)

- 배경: 오늘 gradient 측정(`local/work/grad_norm/out/summary.md`)에서 BC 전역 clip(1.0)이 40/40 batch에서 걸리고(배율 0.09~0.2), clip 뒤 보조 모듈([032-R24][s032] `aux_jepa`·`aux_priv`, 약 180만 파라미터) 원소별 gradient가 1e-6~4e-7로 AdamW eps 1e-5보다 훨씬 작았다.
- 예상(조사 전): |g| ≪ eps이면 Adam step이 √v̂/eps 배로 줄어 보조 모듈이 거의 안 배운다.
- 결론
  - **보조 모듈 step은 eps 때문에 정상 Adam의 약 1/5~1/15다(실측, Checkpoint 2·GN·t2 기준 aux_jepa 1/7~1/10; S1 끝 aux_jepa 1/16, RL 1/2.3~1/3.6).** BC 원소의 99.8~100%(RL 93~95%)가 √v̂ < eps.
  - 그래도 **안 배운 것은 아니다**: S1에서 `aux_jepa` 0.96 → 0.09, 가중치가 초기값 norm의 0.86배만큼 이동. S1e2(lr 1/2)에서도 초기 norm의 0.36만큼 이동, S2 이후(lr 1/10 단계)는 거의 정지.
  - **eps를 고쳐도 몸통(Core·인코더) update에서 JEPA가 차지하는 몫은 그대로다(추론).** 몸통 gradient에서 보조 손실 몫은 norm 기준 0.1~1.4%(1 batch)이고, 몸통 원소의 √v는 주 손실이 정하므로(추론) 몫은 eps와 무관하다. 몫을 바꾸는 것은 λ뿐이다(안 A는 몸통 step 전체를 키울 뿐).
  - eps는 **Core(1,446만, 전체의 약 55%)도 줄인다**: S1 동안 step이 정상의 약 0.35~0.39배, S2 끝 0.51배, Checkpoint 2·GN·t2 0.62~0.66배. S1·S2는 [041-R4][s041] 학습 단계, GN은 [032-R26][s032] 공간 인코더 GroupNorm, t2는 누출 수정 최종 가중치([timeline](../../timeline.md) 2026-11-18).
- 산출물: `local/work/aux_eps/`(스크립트 `optim_state.py`·`optim_s1.py`·`rel_step.py`·`drift.py`·`logs.py`·`split.py`, 결과 `out/`).
- 진단(7절, 같은 날 사용자 승인): t2 몸통을 고정하고 예측기만 다시 맞추면 떼어 둔 판 aux_jepa가 0.053 → 0.031(eps 1e-5, lr 3e-5 일정·3,258 update) → 0.022(eps 1e-8, 같은 조건)(실측). 예측기는 지금 몸통에 대한 최적에서 멀고, eps가 거기로 가는 속도를 늦춘다. 원인이 몸통 이동인지 단순 미수렴인지는 구분 안 됨(추론).
- 학습·게임 실행 없음(7절은 고정 몸통 위 예측기만 따로 맞춤, 체크포인트 변경 없음), Linux 호스트 접근 없음.

## 2. 체크포인트 optimizer 상태 (실측)

- 방법: `optim-main.safetensors`(`ckpt.py` `save_optimizer`: 파라미터별 `exp_avg`·`exp_avg_sq`·`step`, f32)를 CPU에서 읽음. 편향 보정 √v̂ = √(v / (1 − β2^step)), m̂ 동일. step은 모든 파라미터가 같음(BC 2844·2844·3258, 각 run 시작에서 optimizer 새로; S1 5000·39096, S2 11387, RL 204).
- 감쇠 = √v̂/(√v̂+eps). "step 비" = ‖m̂/(√v̂+eps)‖ / ‖m̂/√v̂‖(현재 m̂로 본 실제 step 크기 ÷ eps 없을 때).

### 4.1 측정 사실

| 항목 | 값 |
|---|---|
| 보조 가중치 이동(고정 seed 초기값 재생성과 비교, `drift.py`, 초기 norm 대비) | aux_jepa: 같은 초기값 λ 비교 run 3,000 update 0.36, S1 5,000 0.51, S1 끝 0.86, 이후 모든 체크포인트 0.92~0.93. S1 끝 → S1e2 사이 36%, S2 이후 인접 체크포인트 사이 2.5~9%(win_open 3.5~15%) |

### 4.2 정규화 (추론)

- 손실이 1 − 코사인이고 정답이 layer_norm이라 `aux_jepa / tgt_std²`보다 "상수 예측 손실"과 비교하는 편이 맞다. 행 평균 방향을 내는 상수 예측의 손실 ≈ 1 − √(1 − s²)(s = `jepa_tgt_std`; s가 차원별 std 평균이라 하한).
- 상수 예측 대비 비: S1 끝 0.31, Checkpoint 2 0.39, GN 0.65(시작·끝 같음), t2 0.58 → 0.47. `aux_jepa / tgt_std²`(0.23 → 0.35, `local/work/gn_loss/std.py`)와 같은 방향.
- 정정(7절 실측): 이 근사는 상수 예측 손실을 과소평가한다. t2에서 실제 상수 예측 손실은 0.161(근사 0.116)이라 t2 끝의 비는 0.47이 아니라 0.33이다. 위의 다른 비도 같은 근사라 상한이고, 서로 비교할 때만 쓴다.
- GN이 인코더 출력(정답)을 바꾼 뒤 예측기가 2,844 update 동안 따라가지 못함. 느린 step과 맞는 모습이나 원인 증명은 아님(정답 자체가 더 예측하기 어려워졌을 수도 있음).
- 정답 std 감소(0.67 → 0.32)는 JEPA가 일으킨 것이 아님: 정답은 stop-grad이고 몸통 gradient의 JEPA 몫이 0.1~1.4%다.

### 4.3 얼마나 느린가

- |g| ≪ eps 영역에서 Adam step ≈ lr·m̂/eps = **lr/eps 배 SGD+모멘텀**(S2 최고 lr 3e-5 → 3, S1 3e-4 → 30). 그래서 이 영역에서는 Adam 본래의 크기 불변성이 사라지고 step이 λ·clip 배율에 비례한다.

- 순서 기본안(미확정)

  2. 진단에서 여지가 크면 B를 t2에서 S2 일정으로 3,000 update × 2 run(기준·B, 같은 data seed), 보조 손실·상수 예측 대비 비·대상 맵 val 행동 NLL([measurement_protocol](../../guide/measurement_protocol.md))·optimizer step 비를 비교.
  3. A는 Core까지 바뀌므로 B와 따로, 더 긴 run에서만.

  - 예측기(JEPA k 1·8·32, priv)를 체크포인트 가중치에서 시작해 AdamW(β 0.9·0.999, wd 1e-4, 학습과 같은 손실 꼴·λ)로 f32에서 다시 맞춤. 한 step = 학습 시퀀스 24개(무작위, 실제 학습 batch는 32 레인).
  - 손실에 clip 배율 0.194(t2 측정 중앙값)를 곱해 gradient 크기를 학습과 맞춤. eps 1e-5 대조군의 처음 50 step 예측기 gradient RMS는 1.0e-6으로 t2 학습 실측(clip 뒤 1.2e-6)과 비슷함.
  - lr은 일정. 학습의 warmup·cosine은 쓰지 않음.
  - 상수 예측 = 학습 레인 정답 평균 방향(k별), priv는 학습 레인 평균.
- 산출물: `local/work/aux_eps/diag/`(`collect.py`·`fit.py`, `out/fit.json`·`out/curves.md`, 로그). 모은 h(2.2 GB)는 지움(`collect.py`로 다시 만듦).

### 7.3 해석

| 구분 | 내용 |
|---|---|
| 실측 | 같은 lr·같은 update 수에서 eps 1e-8은 대조군보다 aux_jepa가 30% 낮음(0.0314 → 0.0220). 대조군 3,258 step 값에 eps 1e-8은 100~200 step에 도달(200 step 0.0304). 가중치 이동은 lr 3e-5에서 약 9배(2.5% → 23%), lr 3e-4에서 약 7배(14% → 99%). 2절의 step 비(1/7~1/10)와 맞음 |
| 실측 | 대조군도 지금 예측기보다 41% 낮아짐(0.0530 → 0.0314). 몸통을 고정하면 eps 1e-5로도 크게 내려감 |
| 추론 | 예측기는 지금 몸통에 대한 최적에서 멀다. 그 원인이 학습 중 몸통 이동(정답 분포 변화)인지, 정지된 정답에서도 eps 감쇠·낮은 lr 때문에 수렴하지 못하는 것인지는 이 진단으로 가를 수 없다. t2 run 로그의 0.031(처음 100 update, `local/work/aux_eps/out/logs.md`) → 0.054 상승은 같은 run의 `jepa_tgt_std` 증가(0.32 → 0.47)와 겹쳐 뒤처짐의 근거로 약하다. eps는 최적으로 가는 속도를 가중치 이동 기준 약 1/7~1/9, 손실 기준으로는 그보다 더 늦춘다. 실제 t2 run은 평균 lr이 대조군의 절반쯤(cosine)인데도 가중치를 대조군만큼 움직였다(2.6% 대 2.5%) |
| 실측 | 상대 감소는 k1이 가장 큼(eps 1e-8 두 조건 0.042 → 0.009~0.013, 상수 대비 0.26 → 0.05~0.08). 절대 감소는 k32와 비슷(0.064 → 0.026~0.031) |
| 실측 | aux_priv는 여지가 작음(0.00159 → 0.0012~0.00149). lr 3e-5에서는 eps 1e-8이 더 내리고(0.00149 대 0.00132), lr 3e-4에서는 차이 없음. 오래 돌리면 학습 레인과 떼어 둔 판 차이가 벌어짐 |
| 한계 | 몸통 고정이라 몸통이 받는 JEPA 압력(3절, 0.1~1.4%)이 어떻게 바뀌는지는 이 진단으로 알 수 없음. 학습 중 효과는 5절 순서 2(B안 run 비교)로만 확인됨. 떼어 둔 판도 t2 학습 데이터임 |
