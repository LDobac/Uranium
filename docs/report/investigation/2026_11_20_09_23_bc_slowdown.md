## 3. 재현 측정 (Windows CUDA 호스트 단독, `bench bc`)

- 명령: `python -m uranium bench bc --dataset replays/shards/{stardata,community,scr_ladder,personal,botgen,dagger_m2} --config config/bc_m2_teacher_t2.toml --stage s2 --backend cuda --groups 2 --updates <n> --json …`(t2 설정, 새 가중치 seed 1, 레인 그룹 2 = 실제 run과 같음).
- 시작 전 GPU에 다른 계산 프로세스 없음. 바꾼 것은 환경변수·실행 셸만. 메모리는 프로세스 전체 상주(RSS)와 GPU 최대 할당.

| 경우 | 실행 셸 · 바꾼 것 | update | 중앙값 초 | 평균(워밍업·재컴파일 포함) | GPU 최대 GiB | 상주 최대 GiB | 손실(update 40) |
|---|---|---|---|---|---|---|---|
| A 기준 | 코드 페이지 949, 기본값(커널 불림) | 60 | **1.53** | 1.82 | 4.68 | 9.70 | 12.91055 |
| B | 949, `URANIUM_ENTITY_ATTN=torch` | 60 | **3.28** | 3.65 | 9.10 | 9.18 | 12.91007 |
| C | 65001(UTF-8), 기본값 → 로그에 `not built` | 40 | **3.30** | 3.29 | 7.75 | 8.27 | 12.91097 |

- B/A = 2.15배, C/A = 2.16배. 학습 로그의 3.04/1.44 = 2.1배와 맞다.
- 손실은 세 경우 bf16 반올림 차이 안에서 같다(같은 수식, [032]-R19).
- 기준 구현은 GPU 메모리를 약 2배 쓴다(bias·점수·확률 텐서를 만듦, [pytorch_opt] 2.12절).
- [pytorch_opt] 2.12절(10-24)에서는 CUDA에서 커널 이득이 7%였다. 지금 2배인 이유(compile·graph 경로, 엔티티 수 등)는 분해하지 않음.

### 원인 지점 확인
| 확인 | 결과 |
|---|---|
| 949 콘솔에서 새 빌드 디렉터리로 `kernels.load("attn_bias")` | 빌드·로드 성공(약 48초) |
| 65001 콘솔에서 새 빌드 디렉터리 | `not built ('cp1' codec …)` |
| 65001 콘솔에서 이미 빌드된 디렉터리 | 같은 실패(빌드가 최신이어도 실패) |
| 실패 위치 | torch `cpp_extension.get_compiler_abi_compatibility_and_version`이 `cl` 출력(UTF-8)을 `oem`(949)으로 디코드 → `UnicodeDecodeError`. 이 함수는 이 예외를 잡지 않고, `python/uranium/kernels/__init__.py` `load()`가 잡아 기준 구현으로 넘어감 |
| 65001 콘솔 + `TORCH_DONT_CHECK_COMPILER_ABI=1` | 이미 빌드된 디렉터리·새 디렉터리 모두 로드 성공 |
| 이 세션 도구 셸 | PowerShell 도구는 65001, Bash 도구는 949 |

## 6. 같이 본 것

- 같은 실패가 남은 로그: 11-19 aux-eps 세 run(+ 표본 b)만. 11-03 `runs/concede_it_20261103/rl.log`, 11-07 `runs/mix/score_e1_orig.log`에도 같은 줄(그때 RL·채점도 기준 구현).
- 추론 서버도 같은 로더를 쓴다(`agent/infer.py` `kernels.warm`). 65001 콘솔에서 띄운 게임·평가는 기준 구현으로 돌았을 수 있다(속도만, 수식 같음). 범위는 확인하지 않음.
- [model_scaleup] 크기 실측(`local/work/size_probe/`)은 `switches`에 설정값만 남아 커널이 실제로 불렸는지 기록으로 확인할 수 없다. 확대 일정(×4.5/update)을 쓰기 전 커널 로드를 확인하고 다시 재는 것이 안전(추정).
- 부수 발견(추정): 커널 빌드 캐시는 소스 경로가 들어간 명령으로 구분돼, 메인 사본과 worktree가 번갈아 쓰면 매번 약 45초 다시 빌드한다(캐시 `.ninja_log`에 컴파일 18회, 명령 지문 11종). 다른 프로세스가 같은 `.pyd`를 쥐고 있으면 연결 단계가 실패할 수 있다(연결 기록이 없는 컴파일 2건). 이번 느려짐과는 무관(빌드가 최신이어도 디코드 실패, 3절).
