## 1. 퇴보는 실제다 — AC1 별도 재측정은 하지 않는다

AC1 측정과 c0 점검의 조건 차이는 seed_base(44000/43000)와 판 수(30/40)뿐이다(둘 다 stochastic, 60분, 항복 없음, 두 맵 반반, 로컬 hostd). stochastic이라 시드는 판을 가르지 않는다.

| 비교 | AC1 | rush-s3 c0(= rush-s2 끝) | Fisher p |
|---|---|---|---|
| T0 러시 승 | 14/30 | 5/40 | 0.002 |
| UAB12풀 승 | 11/30 | 0/40 | 2.5e-5 |
| 막음(두 상대) | 20/60 | 1/80 | 7e-8 |
| BC T0 승 → c0 | 11/30 | 5/40 | 0.023 |

c1(1.5M)도 11/80 vs AC1 25/60(p = 0.0003). 계보: AC1 47% → rush-s1 2.4M 37%(같은 조건 30판, 차이 없음) → rush-s1 끝 3/10 → rush-s2 1.37M 2/10 → rush-s2 끝 12% → rush-s3 1.5M 18%. **rush-s1 후반~rush-s2에서 BC 아래로 떨어졌다.** 다음 run을 AC1에서 시작하면 드라이버의 c0 점검이 같은 조건의 AC1 측정을 학습과 동시에 준다.

## 2. 무엇이 나빠졌나 (행동)

AC1은 `runs/rushladder_20261103/*/features_final.json`, c0는 `runs/rush3_20261104/held/c0/*/g*.json`(SCV 5초 간격).

- 핵심: **저글링이 도착하기 전**(UAB12 3:06→3:30, T0 3:30→4:00)에 SCV 5기를 잃고 생산도 17기에서 멈춘다. 일꾼이 본진 밖으로 나가 죽는 것으로 보인다. 도착 뒤 30~40초 안에 붕괴(AC1은 40~60초, 1/3 버팀). 빌드는 그대로이고 바뀐 것은 일꾼 운용이다. AC1에서 버틴 판의 차이는 도착 때 마린 수(6 vs 3, UAB12)였다.
- 가설(리플레이 미확인): `rush-s1` 학습 판의 58%(223/383)가 저글링 도착 2:45~3:32인 상대(ZZZKBot·오버풀·UAB 기본·9풀링, 승률 0~16%)였고, 정찰로 상대를 구별하지 못해 "3시 무렵 일꾼을 내보낸다"는 시간 조건 습관을 배웠다 — T0·12풀에는 너무 이르다. c0 리플레이 몇 판의 3:00~3:40을 보면 확인된다.

확인된 구조적 원인:
- **노출 부족**: `rush-s3` 1,209판 중 T0 45·UAB12 54판(각 4%).
- **낭비**: 학습 조건 승률 ≤ 15% 상대가 러시 판의 33%(`rush-s3` 172/525), `rush-s1` 58%.
- **단 측정 조건 불일치**: 평가(항복 없음) 63%/57%였던 9풀10링·12링이 학습(항복 켬)에서 34%/10%. 항복이 "무너졌다 회복한 승"과 "무너졌는데 상대가 못 끝낸 무"를 모두 패로 만들어 학습 승률 ≈ 막음 비율이 된다. 그래서 band 중심 0.5에 닿는 상대가 9풀(82%)뿐이고 나머지는 0.22~0.29 → 사실상 균등 선택.
- **step 배분**: 운영형 판 결정 3,000~4,000 vs 러시 1,000~1,500 → 그룹 0.5/0.5가 step 61%/27%. 실제로 오른 것은 운영형 승률(64→71%)뿐.
- **개선 없는 드리프트**: action 엔트로피 0.79(AC1) → 0.98, KL 0.02 → 0.06.
- **출발점 게이트 없음**: 다섯 run 연속 직전 run의 LATEST에서 이어 갔고 같은 조건 측정으로 고른 적이 없다.
