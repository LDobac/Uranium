# M4 디싱크 판정 비결정성 (2026-10-18)

## 요약
- stardata p16을 다시 build했을 때, 원래 build에서 디싱크(`replays differ`)로 제외됐던 리플레이 2개가 정상으로 판정됐다.
- **원인은 OpenBW 시뮬레이션이 아니라 브리지 shim의 유닛 참조였다.**
  - shim은 `order_target`(그리고 `loaded_in`)에 BWAPI `getOrderTarget()->getReplayID()`를 그대로 넣었다.
  - 대상이 죽었거나 BWAPI가 추적하지 않는 유닛이면 BWAPI 객체에 초기화되지 않은 `replayID`와 `exists()`가 남는다. 같은 리플레이를 재생해도 값이 실행마다 달랐다(0, 3, 0x0AD00000 등).
  - 040-R8 두 번 재생 검사(재생 A와 B의 관측 해시 비교)가 이 값 때문에 어긋나서, 정상 리플레이를 디싱크로 버렸다.
- **수정:** 유닛 참조는 같은 관측의 유닛 목록(`visible_to_self` 통과 유닛)에 있는 유닛만 가리키고, 그 밖이면 `None`이다(spec 011 구현 메모). 시야 밖 유닛 id 노출(010-R5)도 함께 막힌다.

## 재현 (Windows, 같은 PC, 같은 바이너리)
| 확인 | 수정 전 | 수정 후 |
|---|---|---|
| `nondet` 12회(리플레이 A, 3,602관측) | 2회 불일치. 마지막 구간 관측 하나의 마린 `order_target`만 다름 | 12회 모두 동일 |
| build 판정 10회(리플레이 2개, `--jobs 2`) | 10회 중 1회 `replays differ` | 20/20 정상 |
| 전체 build의 `replays differ` 91개 시점(stardata) | – | 2회 판정 모두 91/91 정상 |

- 해시 쌍이 원격 Linux 추출 PC의 기록과 같았다(A와 B만 뒤바뀜). 그래서 OS나 플랫폼 차이가 아니라, 실행할 때마다 두 값 중 하나가 나오는 문제다.
- 처음에는 `exists()`만 확인하는 수정을 시도했다. 그러나 91개 중 13개가 여전히 흔들려서 `exists()`도 믿을 수 없다고 판단했다. 그래서 관측 유닛 포인터 집합으로 판정하게 바꿨다.
- 시뮬레이션 자체(위치, 체력, 이벤트 등 다른 모든 필드)는 매번 같았다.

## 영향
- **전체 build:** 정상 기록 35,870개에 대해 `replays differ`로 제외된 시점이 96개(0.27%)다. stardata 91, community 3, scr_ladder 2.
  - 같은 엔진으로 같은 리플레이를 재생하면 A와 B가 달라질 이유가 없다. 그래서 이 96개는 모두 이 문제로 잘못 제외된 것으로 본다(stardata 91개는 수정 후 전부 정상 확인).
  - 데이터가 0.27% 덜 들어간 것일 뿐, 기존 shard를 다시 build할 필요는 없다.
- **기존 shard의 `order_target`:** 쓰레기 값이 섞였을 수 있다. 다만 feature 추출(030·031)이 이 필드를 쓰지 않아 BC 입력에는 영향이 없다. `loaded_in`은 실린 유닛의 수송선이 항상 관측되므로 값이 바뀌지 않는다.
- **실전·RL 관측:** 같은 shim을 쓰므로 같은 쓰레기 값이 나올 수 있었다. 이것도 feature에는 쓰이지 않는다.

## 잘못 제외된 96개 시점 추가 (2026-10-18, 사용자 결정)
- **build:** 이 PC에서 수정된 브리지와 같은 커밋의 `uranium-replay`로 해당 리플레이 93개만 로컬 디스크에 build했다.
  - TvT 7개는 반대쪽 시점이 이미 기존 shard에 있다. 그래서 잘못 제외됐던 시점만 골라 shard를 새로 썼다(중복 0).
- **추가 위치:** 각 소스에 새 파트 폴더 `shards/<src>/fix-desync-p0/`를 만들었다.
  - stardata 91게임(shard 8개), community 3게임(1개), scr_ladder 2게임(1개)
  - 기존 shard 파일은 건드리지 않았다.
- **복사 검증:** `.part` 이름으로 복사한 뒤 해시를 대조하고 이름을 바꿨다. 공유 폴더에서 다시 읽어 디코딩도 확인했다.
- **records:** `records/fix-desync/<src>.jsonl`(96줄)에 두었다.
  - build 재개는 같은 폴더만 읽고, 이 리플레이는 기존 records에 이미 있어 다시 처리되지 않는다.
  - 폴더 전체를 집계해도 기존 `replays differ` 기록과 중복으로 세지 않도록 하위 폴더에 따로 두었다.
- **manifest:** 세 소스를 다시 만들었고 `--verify`를 통과했다(stardata 1,848, community 42, scr_ladder 44개 파일).
