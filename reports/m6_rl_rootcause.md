# RL 정체·퇴보 원인 분석 (2026-11-04)

- 배경: `rush-s1`~`rush-s4`(러시 커리큘럼 계열)에서 초반 러시 방어가 오르지 않고, 3차 자문(`reports/m6_rl_stall_advice3.md`)은 "rush 계보가 AC1보다 퇴보"로 진단해 `rush-s4`를 AC1에서 다시 시작했다. 그런데 `rush-s4` c0 점검(AC1 `ckpt-3133569`, seed 43000)이 막음 6/80으로 사다리 측정의 AC1 막음 20/60(33%)과 크게 달랐다. 사용자 요청으로 고성능 모델(fable, effort 최고)에게 **해결안이 아닌 원인 분석**을 맡겼다(읽기 전용, 파일·프로세스 변경 없음).
- 근거 데이터: `reports/m6_rush_ladder.md`, `runs/rushladder_20261103/`(features_final.json, dumps), `runs/rush4_20261104/`(summary.md, held/c0, rush-s4/logs/train.csv·games.csv, eval/c0-eval.log), `<shared>/eval/{rushladder-20261103, rushladder-20261103c, rush4-20261104/c0}`, `runs/diag_20261104/notes.md`. 분석 스크립트·명령 스트림 JSON은 임시 폴더에만 두었다(저장소 밖).

## 1. 요약 — 원인 순위

| # | 원인 | 확신 | 설명하는 범위 |
|---|---|---|---|
| 1 | AC1 두 측정의 차이는 **시드가 정하는 시작 위치 → 상대 러시 도착 시각 차이**다. 정책 차이가 아니다 | 확인됨 | "퇴보" 진단 전체, `rush-s4` 판정 기준(33%·40%·45%·55%)의 근거 |
| 2 | 러시 판 승패가 거의 **외생 변수**(시작 위치·상대 탐색 순서)로 정해지고, privileged critic이 그것을 거의 완벽히 예측해 정책이 바꿀 수 있는 advantage가 거의 없다 | 수치 확인됨 / 기전 가능성 높음 | 2.3M step 동안 정책이 거의 안 움직인 것 |
| 3 | 상대 선택(band)·자기 모방이 **가장 쉬운 러시 상대(9풀히드라)로 쏠린다**. 승 판 = "러시가 제대로 안 온 판"이라 자기 모방은 방어가 아니라 운을 복제한다 | 확인됨 | 러시 신호 밀도, 자기 모방 무효과 |
| 4 | 필요한 방어 행동(벙커 2:45 전·마린 탑승·SCV 수리 조합)이 **BC 사전분포에 거의 없고**, 결정 단위(약 0.45초·12기 묶음·명령 1개)로는 SCV 미세 조작이 거칠어 이른 도착(3:10)은 AC1도 9%만 막는다 | 가능성 높음 | 무작위 탐색이 성공을 못 찾는 이유 |
| 5 | **점검 판 수의 통계력 부족**: 10판 ±30%p, 30~40판 ±15%p. 지난 run들의 "변화 없음·퇴보·개선" 결론 대부분이 잡음 안 | 확인됨 | 지난 결론 재검토 |

## 2. 측정 문제 — AC1 불일치는 해소됨

- **같은 가중치·같은 조건**: 두 평가 모두 `main@7f7a75b4f94d` 적재. 맵 해시·맵 사전계산·stochastic·실제 last_failed·결정 빈도(1,000프레임당 관측 105~113)·명령 수·실패·거절 수가 같다. 호스트·학습 동시 실행·코드 변경(11-03 이후 agent 변경은 항복·정찰 지표 기록뿐)은 원인이 아니다.
- **다른 것은 시드뿐이고, 시드가 시작 위치를 정한다**: `third_party/patches/0002-openbw-fixed-start-seed.patch`가 `URANIUM_SEED`를 OpenBW 난수 상태에 넣어 시작 위치를 고정한다. 평가 plan은 `seed_base + n`(`crates/uranium-runner/src/plan.rs:289`)이라 연속 시드의 시작 위치가 강하게 상관된다(사다리 T0 30판: n 1~22는 우리가 모두 오른쪽·저그 왼쪽, 23~30은 반대). 학습 판은 game id 해시 시드(`crates/uranium-league/src/run.rs:457`)라 분포가 다르다.
- **T0는 시작 위치를 고정 순서로 훑는다**(`crates/uranium-scripted/src/lib.rs:385`, 적 건물을 모르면 `start_locations` 인덱스 순 첫 미탐색 위치로 어택땅). 첫 웨이브(저글링 6기)는 두 측정 모두 2:33~2:42 출발(리플레이 명령 스트림 파싱):
  - 사다리(seed 44000, T0 30판): 첫 목표가 우리 본진인 판 **0/30** → 1~2곳을 거쳐 도착 p50 4:08.
  - `rush-s4` c0(seed 43000, T0 40판): 첫 목표가 우리 본진 **33/40** → 첫 SCV 손실 p50 3:33, 붕괴 p50 4:10.
  - 같은 AC1의 조건별 결과(c0): 첫 목표 적중 33판 → 막음 3(9%), 승 9 / 빗나간 7판 → 막음 2, 승 2. 사다리 막음 10/30(33%)은 전부 "빗나간" 조건이다. **AC1은 조건별로 약 9% / 약 30%이고 두 측정 모두 맞다.**
  - UAB12도 같다: 정찰 드론이 우리 본진에 닿는 시각 p50이 사다리 2:45, c0 약 2:03 → 저글링이 약 40초 일찍 옴 → 막음 10/30 vs 1/40.
- **결론**: 3차 자문의 "AC1 20/60 vs rush-s2 끝 1/80, p 7e-8 퇴보"는 조건이 다른 표본 비교였다("stochastic이라 시드가 판을 가르지 않는다"가 틀림). 같은 시드(43000) 비교: 막음 AC1 6/80 vs rush-s2 끝 1/80(Fisher p 0.12), T0 승 11/40 vs 5/40(p 0.16), UAB12 2/40 vs 0/40(p 0.49) — **유의한 퇴보 없음**. "저글링 도착 전에 일꾼을 잃는 습관"도 틀렸다(AC1도 c0에서 3:23~3:33부터 SCV를 잃고, 그때 저글링이 실제로 와 있다).
- 사다리의 "AC1 막음 33%"는 학습 조건(해시 시드, 첫 목표 적중 확률 이론상 1/3)보다 후한 기준값이었고, `rush-s4` 판정 기준(0.75M 40%, 1.5M 45%, 3M 55%)이 여기서 나왔다. 학습 판에서 AC1급 정책의 T0+UAB12 미니게임 승률은 처음부터 약 25~29%였다.
- 같은 시드(43000) 계보: `rush-s2` 끝 승 5/80 → `rush-s3` 1.5M 11/80 → AC1 13/80 → `rush-s4` 1.5M(T0 9/33 진행 중): 모두 구별되지 않음.

## 3. 학습 신호 경로

- **판정 결과는 learner에 제대로 들어간다**(확인됨): `trajectory.rs` `on_end` → `hold_terminal`로 r_win을 마지막 결정에 더하고 terminal(bootstrap 0). `games.csv` RushJudge 439판 모두 끝 프레임 11,521, r_win ±1, `judge_scv ≥ 8` 불일치 0. V-trace·UPGO(`python/uranium/rl/returns.py`)는 Rust 기준 구현과 같은 재귀, 부호·ρ 절단·세그먼트 겹침 bootstrap 정상. 버그는 찾지 못했다.
- **off-policy·KL·엔트로피는 원인이 아니다**(확인됨): ρ 평균 0.975, 지연 2.8~3.2 update, 버림 0, KL 0.026 → 0.035(계수 0.095 → 결정당 벌점 약 0.003), 엔트로피 0.78 → 0.85. 정책은 2.3M step 동안 거의 움직이지 않았다.
- **advantage가 작은 이유**: value_loss_win 0.0025(±1 스케일 RMS 오차 약 0.07). privileged critic(상대 자원·유닛 수)은 결과를 거의 완벽히 안다. 우리 시작 위치(관측)와 T0 저글링 수(privileged)로 도착 시각(3:10 vs 4:00)이 일찍 정해지므로 V가 일찍 수렴하고, 정책 행동이 V를 바꾸는 폭은 adv_rms_win 0.06~0.07 중 극히 일부다. λ 0.95(추적 깊이 약 20결정 ≈ 9초)에서 방어 구간(2:30~4:00, 약 200결정)에 8:00 판정이 닿는 길은 V뿐인데 그 V가 행동에 둔감하다.
- **자기 모방**(확인됨): `sil_loss` 0.04~0.08, `sil_pos_frac` 0.8~0.95이지만 A⁺ = max(1 − V_win, 0)에서 privileged V_win이 이미 높아 A⁺가 작고 w_pg 0.05라 기여가 작다. 버퍼 내용이 더 문제다: 러시 승 355판 중 9풀히드라 189(53%), 최근 300판 67/121(55%). 승 판 `judge_scv` p50 24~28 — SCV를 거의 안 잃은 판, 즉 "러시가 늦게·약하게 온 판"이다. 복제되는 것은 방어가 아니다.
- **상대 비중**(확인됨): 승률 표 x = T0 0.08·UAB12 0.13·10링 0.16·9풀히드라 0.73 → band(폭 0.3)로 9풀히드라가 러시 판의 47%. T0·UAB12는 누적 465/1,364판(34%), step으로는 더 적다. T0 판은 54%가 약 6.4분 붕괴 항복, 12% 섬멸, 28% 판정 승, 6% 판정 패.
- 보상 크기(T0 판): 패배 r_survive 원값 0.27(×0.1), r_value −1.74(×0.05) → 판당 약 −1.06, 승 +1.1. 보조 보상이 승패를 뒤집지 않는다(설계대로).

## 4. 과제 난도·표현력

- 이른 도착(3:10, 저글링 6 → 4:00 18 → 5:00 26)을 막으려면 배럭 1:40 → 벙커 약 2:45 착공·3:10 완성 → 마린 탑승·SCV 수리·일꾼 동원 순서가 필요하다. 원시 행동은 모두 있다(`Build_Bunker`, `Load_Unit`, `Repair_Unit`, `Hold`, spec 034). 그러나 F2 기준 BC가 3:30 전에 벙커를 한 번이라도 고를 판당 확률 0.2~0.3, 2번째 배럭 0.3~0.4이고, 결정 간격 약 0.45초·선택 12기·결정당 명령 1개라 SCV 미세 조작이 거칠다. 모델은 판당 10~16기 SCV를 끌어내 싸우지만 잃는다. AC1이 이른 도착에서 9%를 막으므로 불가능은 아니지만 성공이 너무 드물어 보상 신호가 쌓이지 않는다.
- 늦은 도착(4:00)이면 AC1·BC도 약 30%를 막는다 → 난도의 큰 몫이 상대 도착 시각이라는 외생 변수에 있다. 학습 조건(해시 시드)에서는 이론상 1/3이 이른 도착.

## 6. 아직 모르는 것과 가장 싼 확인

1. **critic이 시작 위치로 결과를 '미리' 아는가**: learner에서 러시 판 V_win(privileged)을 1:30/2:30/3:30에 "첫 목표 적중/빗나감"별로 기록(로그 한 줄). 코드 변경 없이 하려면 c0 리플레이 40판을 shard로 만들어 privileged 포함 forward.
2. **점검 판별력 올리기**: c0·c1 리플레이 80판을 명령 스트림(파서만, OpenBW 불필요, CPU 몇 분)으로 "첫 목표 적중/빗나감"으로 나눠 체크포인트별 조건부 막음을 비교.
3. **시드 → 시작 위치 대응**: `seed_base + n` 평가는 시작 위치가 편향·상관된다. 해시 시드나 층화 보고 없이는 어느 run 점검도 학습 조건과 맞지 않는다(확인된 사실, 조치는 사용자 결정).
4. **band·자기 모방 쏠림의 step 기준 크기**: `games.csv` decisions 합으로 바로 계산 가능(지금은 판 수 기준만).
