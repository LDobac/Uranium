# RL 9차 자문 — 교사 클론 판정과 다음 단계 (2026-11-07)

- 배경: 교사 전용 클론 `bc-tclone-e5`(5 epoch)가 128판 점검에서 이른 18/64·늦은 28/64로 처음 크게 올랐다(BC 2·19). 사용자 위임으로 fable(effort 최고) 자문, 읽기 전용(분석은 이 PC에서 가볍게).

## 1. 판정
1. **전이 확인**: 교사 데이터를 희석하지 않으면 실전으로 옮겨진다(8차 A 문턱 통과).
2. **비중보다 "지나간 횟수"**: 벙커 top-1은 FT(12.5%, 1 pass) 26.5% = 클론 e1(100%, 1 pass) 27.2%, 5 pass 62.7%. 생산 recipe는 교사 데이터를 7번 이상 지나가야 한다.
3. **SCV 약점은 클론만의 이탈**: 4:00까지 SCV 지시 p50 클론 8(교사 17, BC 16). 교사는 CC가 비면 8프레임 안에 다시 찍어 "CC가 오래 빈 상태"가 데이터에 없다 → 한 번 놓치면 본 적 없는 상태에서 멈춘다. 사람 데이터를 섞으면 고쳐진다.
4. **벙커 자리는 병목이 아니다**: 벙커 지시 47판 → 실제 착공 44판. 격차는 시각(3:00 전 착공 23/64, 교사 48). 건설 위치 보정은 지금 하지 않는다.
5. argmax 0/64는 지연 헤드·채취 모드 퇴화 — 점검·RL은 stochastic이라 무시.

## 2. 결정 패키지
1. **생산 recipe `bc-mix-s1`(이 PC CUDA, 약 2시간)**: `--s2 --init bc-s2e2-pt/ckpt-11387`, 사람 4출처 + botgen, `[data.subsample] fraction = 0.036`(사람 약 0.83M step ≈ 교사 0.82M → 교사 step 50%, `bc-epoch`로 50 ± 3% 확인), `keep_sources = ["botgen"]`. **7 epoch `--init` 체인**(epoch당 약 840 update), lr 3e-5 → 3e-7·warmup 5%·cosine, **epoch마다 `data.seed` 3…9**(7 epoch 합 ≈ S2 1/4). spec 041-R21 개정(메인 임시 결정, 사용자 확인). epoch마다 액션별 hold-out 채점. e7 벙커 top-1 < 70%이고 epoch당 ≥ 2%p 오르면 e10까지, e7 벙커 < 50%면 보조 arm(`--init bc-tclone-e5`에서 같은 혼합 3 epoch).
2. **병행: 클론 e5 운영형 점검**(운영형 4상대 × 10판, 모델판, ROCm 추론): 4:00 전 벙커(선제 벙커 대리), `scv_8m ≥ 16`, CC 지시 ≤ 5:00. 순수 교사 모방체가 선제 벙커를 안 지으면 사용자 제약이 데이터 수준에서 성립.
3. **게이트(채택 epoch)**: G1 러시 128판 이른 ≥ 16/64·늦은 ≥ 24/64(신호: 3:00 전 정찰 ≥ 40/64, 벙커 지시 ≥ 24/64), G2 운영형 40판 4:00 전 벙커 상대별 ≤ 2/10·합 ≤ 5/40·CC ≤ 5:00 ≥ 24/40·`scv_8m ≥ 16` ≥ 24/40, G3 늦은 조건 `scv_4m` p50 ≥ 15, G4 T0 stochastic 100판 승률 ≥ 29%, val500 기록만(65% 아래면 사람 몫 증가).
4. **분기**: 모두 통과 → `rush-s6` `--init <mix> --bc <같은 mix>`(KL 참조를 혼합 모델로 — BC를 참조로 두면 BC에서 확률 ≈ 0인 벙커·정찰을 KL이 지운다). G1 실패 → DAgger(혼합 모델 자기 판을 교사 Brain으로 재레이블, 약 1.5일). G2 실패 → botgen 운영형 +400판 뒤 재실행. G3/G4/val 실패 → `fraction = 0.072`(교사 33%).

## 3. 하지 않을 것
클론 추가 epoch, 클론에서 `rush-s6` 시작, 위치 보정·label smoothing, argmax 판정, 교사 규칙 재수정.
