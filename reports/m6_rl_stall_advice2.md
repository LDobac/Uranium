## 1. 핵심 진단: 학습 신호가 learner에 거의 도달하지 않는다

| 항목 | 값(`rush-s2`, update 875, 170만 step) |
|---|---|
| 학습 step 비중 | 러시 판 12.2%(판 수로는 34%), 운영형 32%, **모델 상대 55.6%**(그중 60분 무승부만 23.6%). `rush-s1`도 모델 상대 62.6% |
| 러시 방어 구간(러시 판 첫 4분) | 전체 step의 **약 4.2%**. `rush-s1`+`rush-s2` 470만 step 중 약 20만 step ≈ 100 update 분량 |
| 사다리 선택 | f_var(감쇠 0.97)로도 러시 7종이 13~16%로 거의 균등. 0% 상대(오버풀·ZZZKBot)에 러시 판의 24% |
| 러시 그룹 | 33-112(23%). 9풀 21-4, T0 4-16, 12풀 2-19, 기본 2-22, 9풀링 4-16, 오버풀 0-20, ZZZKBot 0-15 |
| 정찰과 승리 | 4:00 전 적 본진 발견 판 17/30 승(57%), 미발견 판 0/94 승(혼동 있음) |
| KL | 0.035~0.08(p99 0.18, max 0.31), 헤드별 selected > target_loc > action. **kl_coef 0.097** |
| 엔트로피·ρ·지연 | 붕괴 없음 / 0.94~0.97 / 4.5~6.1, 버림 0 — 오프폴리시 문제 아님 |
| 코드 점검 | 보상 가중치, 항복 r_win, 종료 bootstrap, 판별 배수(PG만), V-trace/UPGO 수식, 엔트로피 부호, KL 방향 — 버그 없음 |

### 원인 가설
1. **신호 밀도:** 커리큘럼이 판 수로는 들어갔지만 step으로는 거의 안 들어갔다(모델 상대 판이 판당 7,000~9,000결정).
2. **advantage가 설계상 작다:** value head가 privileged 입력(상대 실제 자원·유닛)을 받아 1분대에 "진다"를 안다 → 정찰·대비 행동의 1-step advantage ≈ 0(비대칭 critic의 부작용). λ 0.8·결정 간격 0.5초면 추적 깊이 약 2.5초인데 벙커(2:30)와 결과(4:30)는 300결정 떨어져 있다.
3. **KL 0.1이 희귀하지만 결정적인 행동을 막는다(1차 자문과 다른 판단):** 최적해 π ∝ π_BC·exp(A/β). β 0.1에서 BC가 1% 주는 행동을 주 행동만큼 올리려면 advantage 차이 약 0.39가 필요하다. 추정 advantage 0.01~0.03으로는 1% → 1.3%. "첫 배럭 1:40 고정, 벙커 거의 없음"이 네 run 내내 그대로인 것과 맞는다. 또 KL 계수는 run마다 0.1로 다시 시작해 실제로 감쇠한 적이 없다.
4. **희귀 성공은 있다:** 중간 단(T0·12풀) 상대로 막는 판이 약 33% 있으나 step의 1% 미만이라 묻힌다.
5. **측정 잡음:** 점검 10판의 95% 범위가 ±25%p 수준이라 지금까지의 "변화 없음"은 ±15%p 효과를 못 본다.

## 3. 권장 우선순위

| 순위 | 묶음 | 기대 | 싸게 재는 법 |
|---|---|---|---|
| 1 | **신호 밀도**: B1 + B2 + B3 + B5 (+ 가능하면 B6) | 러시 방어 구간 step 4% → 12~15%(B6 포함 20~25%) | 100 update 안에 러시 step 비중 ≥ 35%; 1.5M step에서 러시 판 `scv_4m ≥ 12` 비율 약 45% → +15%p; 3M에서 T0·12풀 40판 막음 33% → 50% |
| 2 | **KL·λ**: A1 + A4 (+ A2) | 희귀 빌드 행동 상한 해제 | 1M step 안에 첫 배럭 시각 폭(p10~p90) > 30초, 러시 판 4:00 전 벙커 > 40% |
| 3 | **자기 모방·막은 판 우선 재학습**(A7) | 이미 있는 성공을 직접 복제 | 1.5M step 안에 막음 대용 지표 추가 +10%p |
| 4 | **시연 사전분포**: C1 우선, C2 보조, 그 뒤 C3 또는 새 `--init/--bc` | 1·2로도 탐색이 못 찾을 때의 수단 | 교사: T0·12풀 막음 ≥ 60%; 파인튜닝 BC: 러시 막음 30% → 50%, val top-1 −0.3%p 이내 |
| 5 | **진단·측정**: F1~F3 + E3·E4·E5 | 다음 결정을 잡음 위에서 내리지 않게 | F2(π_BC(벙커))가 2의 근거 |

- 권장 순서: F 진단 → 1+2를 한 run(`rush-s3`)으로 → 그 run 동안 3·4 구현 → 1.5M step 지표로 3·4 투입 결정. 1과 2를 따로 A/B하면 GPU 하나로 시간이 2배라 권하지 않음.
- 중단 규칙(2 적용 시): action KL > 0.3 지속, anchor 상대 승률 < 30%(60판), action 엔트로피 < 0.4.
- `rush-s2`: c0과 c1M이 구별되지 않아 지금 멈춰도 잃는 것이 거의 없다. `rush-s3` 준비가 하루 안이면 지금 멈추고 진단에 PC를 쓰는 것을 권함. 새 run 출발점은 `rush-s2` LATEST(scout 채널 value head가 맞춰져 있음), anchor는 AC1 그대로.
- 전략 질문: 러시 방어는 UAlbertaBot·ZZZKBot 상대의 필요조건일 뿐이다. 운영형 비중을 올린 병행 run을 선택지로 열어 둘지 사용자 결정.
