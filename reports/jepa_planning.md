- 작성: 2026-11-11
- 성격: 설계 제안입니다. spec 변경도 구현도 아닙니다. 수치·정책은 모두 미확정이고, 기본안은 "기본안(미확정)"으로만 적었습니다.
- 계기: 사용자 결정(2026-11-11). 모델 2 경로(BC → 교사 혼합 → DAgger → RL V-trace, 041-R29·042-R21)는 그대로 진행합니다. 이와 나란히, 모델 2 체크포인트 위에 새 모듈을 얹어 **계획·탐색·제어에 쓰는 JEPA**를 설계합니다(BC 재학습 없음).
- 근거: 저장소(`spec/001`·`012`·`030`·`031`·`032`·`033`·`034`·`040`·`041`·`042`·`050`, `python/uranium/model/`, `python/uranium/agent/infer.py`), 리포트(`jepa_survey.md`, `model2.md`, `pytorch_opt.md`, `m7_scr_bridge.md`, `checkpoint1_rl.md`, `timeline.md`), 웹 문헌(9절에 검증 수준).

## 0. 결론 먼저

1. **지금 모델 2의 JEPA는 행동 선택에 쓰이지 않습니다.** 예측기 g_k는 "k 결정 뒤 내 시야 요약"을 맞히는 학습 전용 보조 손실입니다(032-R24). 행동을 입력으로 받지 않으므로 "이 행동을 하면 어떻게 되나"를 물을 수 없습니다.
2. **계획에 쓰려면 행동을 조건으로 받는 예측기가 필요합니다.** 권장하는 첫 형태는 다음과 같습니다.
   - 지금 결정의 **행동 종류(101개 중 하나)** 를 조건으로 받습니다.
   - 8·32 결정 뒤를 **한 번에 건너뛰어** 맞힙니다(굴리지 않음).
   - 맞히는 것: 내 시야 요약(지금 JEPA 정답), 적 실제 상태(privileged, 학습 정답으로만), 내 상태 몇 가지(SCV 수, 건물 수), 그리고 채점용 결과값.
   - 학습은 모델 2 몸통을 **고정**하고, 저장해 둔 몸통 출력 위에서 작은 모듈만 따로 학습합니다.
3. **쓰는 곳은 "드문 결정 순간의 재정렬"을 먼저 권합니다(4절 A).**
   - 정책이 건물·생산 같은 운영 행동을 고려하는 순간에만 켭니다.
   - 정책이 좋아하는 상위 몇 개 행동 종류만 후보로 둡니다.
   - 후보마다 세계 모델로 결과를 채점하고, Gumbel MuZero 방식으로 정책 확률을 조금 고쳐서 뽑습니다.
   - 계산은 작은 MLP 수십 번이라 1~2 ms 안팎으로 예상합니다. 실시간 예산(관측 뒤 24프레임, 012-R7) 안입니다.
   - 계보 학습을 건드리지 않고, 같은 체크포인트로 켬/끔 짝 비교를 할 수 있습니다.
4. **조사 때 형태 C를 버린 두 이유 중 하나는 풀립니다.** 실시간 문제는 잠재 공간에서 한 번에 건너뛰는 예측이면 비용이 거의 없습니다. 행동 공간 문제는 "행동 종류만" 또는 "정책에서 뽑은 몇 개"로 줄이면 됩니다. AlphaStar Unplugged(스타2)도 정책에서 뽑은 20개 행동만 탐색했고, 뿌리 아래에서는 행동 종류와 지연만 예측했습니다.
5. **다만 정직하게 말하면, 깊이 1의 건너뛰기 계획은 "모델로 학습한 행동 가치 Q"와 거의 같습니다.** 세계 모델 부분이 주는 이득은 셋입니다.
   - 결과 하나보다 풍부한 학습 신호(미래 요약·적 상태·내 상태)
   - 해석 가능성(이 후보를 고르면 벙커 수가 늘고 적 저글링 수 예측이 이렇다)
   - 나중에 깊이 2 이상으로 넓힐 바탕
6. **가장 큰 위험은 "행동이 증거가 되는" 착각입니다.** 사람 데이터에서 벙커는 러시를 본 사람이 짓습니다. 그래서 모델이 "벙커 = 질 상황"으로 배울 수 있습니다(Ortega et al. 2021의 auto-suggestive delusion). 모델이 직접 둔 판(실제로 한 행동이 기록된 판)으로 학습하고, 6절 시험에서 이 착각을 따로 잽니다.
7. **구현 전에 싼 시험을 먼저 하자고 권합니다(6절).** 모델 2 체크포인트(`m2-s1/ckpt-39096`, 11-11 13:24 끝)의 몸통 출력을 한 번 덤프하고, 그 위에서 작은 예측기만 학습합니다.
   - 행동 종류를 조건으로 주면 8·32 결정 뒤 예측이 나아지는가
   - 후보마다 예측이 구별되는가(벙커를 고르면 벙커 수 예측이 오르는가)
   - 상상한 상태의 채점이 실제 결과 순위를 맞히는가, 러시 판에서 벙커를 더 좋게 보는가
   - 덤프는 CUDA 호스트 1~2시간(또는 Linux ROCm 호스트에서 표본을 줄여 3~5시간), 예측기 학습·분석은 CPU 호스트로도 됩니다. 에이전트 코딩은 약 6~9시간입니다.
8. **사용자가 정할 일이 8개 있습니다(8절).** 가장 먼저 필요한 것은 "무엇을 좋은 결과로 채점할지"와 "시험을 언제 어느 장비에서 할지"입니다.

## 1. 목표와 고정 조건

### 1.1 목표

- JEPA형 예측을 **행동을 고르는 데** 씁니다: 계획(plan), 탐색(search), 제어(control).
- 모델 2 체크포인트 위에 새 모듈로 얹습니다. BC를 다시 하지 않습니다.
- 모델 2 계보 학습과 측정(050-R9 경로 측정)을 오염시키지 않아야 합니다. 그래서 첫 단계는 계보 바깥(별도 모듈, 별도 평가)에서 합니다.

### 1.3 시야 원칙

- 정책 입력은 자기 시야만입니다(010-R5, 030-R2). 기억 적 건물은 "마지막 목격 상태 + 경과"뿐입니다.
- privileged(`PrivilegedSummary`: 적 실제 자원·업그레이드·테크·유닛 완성 수·생산 중 수, P = 383)는 lockstep 학습에서만 오고, value 입력과 보조 목표 **정답**으로만 씁니다(010-R10, 030-R9, 032-R11, 2026-11-09 개정).
- 그래서 세계 모델도 **입력은 자기 시야에서 나온 h_t만**, privileged는 학습 정답으로만 씁니다.
- 열린 질문: 학습 때 privileged로 정답을 배운 예측값(p̂, 자기 시야의 함수)을 **실전 채점에 쓰는 것**이 원칙에 맞는지는 사용자 판단이 필요합니다(8절 5번).

### 1.4 행동 구조(031, 034, `heads.py`)

```
1 행동 종류 a ∈ 101개(id 0~100, 0 = NoOp) ── type_mask로 가능한 것만
2 지연 16 bucket(1~32프레임)
3 queued 2
4 선택 유닛 ≤ 12(END 포함 자기회귀)
5 대상 유닛 | 6 위치 128²
```

- 행동 종류 헤드: `type_in(h) → ResMLP×2 → ReLU ⊙ σ(type_gate(c)) (+ 우회로 u) → type_out`. c는 스칼라 문맥, u는 유닛 토큰을 직접 읽는 우회로(032-R21)입니다.
- 이후 헤드는 `ar = Linear(h) + Emb(a) (+ u) + Emb(delay) + Emb(q) + Linear(mean key[선택])`를 이어 씁니다. **이 `ar`은 이미 "전체 행동의 임베딩"입니다**(대상 유닛·위치 제외). 2절 (c)에서 다시 씁니다.
- 샘플링은 forward 안의 Gumbel-max입니다(`gumbel_argmax`). Gumbel MuZero의 "Gumbel-top-k로 중복 없이 뽑기"와 같은 장치라 붙이기 쉽습니다.
- 행동 종류 분포는 뾰족합니다. BC 행동 NLL 약 0.88(Checkpoint 1), 1.12(모델 2 3,000 update), RL 엔트로피 0.85 → 0.58. 실제 고를 만한 후보는 결정마다 몇 개뿐일 것입니다(6절에서 잼).
- 운영 행동은 드뭅니다. 벙커는 BC에서 결정당 1% 미만이었습니다(`m6_rl_rootcause.md`).

### 1.5 executor(031)

- 최소 규칙만 있습니다. `pick_worker`(건설 SCV), `pick_building`(생산 건물)은 결정론입니다.
- 건설 위치는 정책이 고른 타일 그대로이고, 무효면 실패로 기록합니다(031-R2).
- 계획 모듈은 executor를 바꿀 필요가 없습니다. 후보는 `type_mask`가 연 행동 종류로만 둡니다.

### 1.6 가치 헤드(032 §2.6, `value.py`)

| 헤드 | 입력 | 실전에서 | 한계 |
|---|---|---|---|
| win(tanh), build, units, value | h, z, 종족, **privileged** | privileged 자리가 0 벡터 → 실전 승률로 못 씀 | 학습 때는 privileged를 늘 받음 |
| win_open(tanh) | detach한 h, z, 종족 | 씀(항복 판정 031-R12) | MSE 0.86~0.87, 상수 예측(1.0)보다 조금 나은 수준. h로 기울기를 보내지 않음 |

- **세계 모델 채점에 바로 쓸 수 있는 실전용 가치가 약합니다.** 이것이 3절 채점 설계의 출발점입니다.
- 모델 2에는 `aux_priv`(h → privileged 예측, 학습 전용)가 이미 있습니다. 원리상 `win(h, z, 종족, aux_priv(h))`로 privileged 자리를 예측값으로 채울 수 있습니다. 다만 그 입력층은 진짜 privileged로만 학습돼 분포가 다르고, 1.3의 원칙 질문이 걸립니다.

### 1.7 RL에서 정책이 쓰이는 방식(042)

- actor가 `act()`로 샘플하고 **선택한 행동의 헤드별 log-prob**만 기록합니다(전체 로짓은 저장 안 함). V-trace·UPGO 중요도 비율에 씁니다.
- KL(π‖π_BC)은 learner가 BC 모델을 다시 forward해 정확히 계산합니다.
- 세그먼트 T=64, 시작 Core 상태 저장. 경로 2 RL은 `m2-s2e2` 출발, V-trace, `[aux] priv 0.2·jepa 0.1`(042-R21).
- 처리량 측정: 게임이 learner 소비의 약 4배를 만들어 74%가 버려졌습니다(`timeline.md` 10-31). **actor 쪽 계산을 조금 늘려도 학습 처리량은 거의 줄지 않습니다.** 4절 B의 근거입니다.
- RL 정체의 진단된 원인: 필요한 방어 행동이 BC 분포에서 드묾, 시작 위치가 승패를 가름, 신호가 희소함(`checkpoint1_rl.md`). 결정 순간 계획은 "드문 행동을 필요할 때 고르게 하는" 쪽이라 이 원인 하나를 직접 겨냥합니다.

### 1.8 이미 있는 것

| 구성 | 상태 | 계획에 쓸 수 있나 |
|---|---|---|
| JEPA 예측기 g_k(k=1·8·32), MLP 512→512→512 | 학습 전용, `act()`에 없음(032-R24, AC14) | 행동 조건이 없어 그대로는 못 씀. "행동 없는 기준선"으로 씀 |
| JEPA 정답 y = LN([e_pool, s_pool]) | 같은 forward에서 stop-grad | 새 예측기의 정답으로 그대로 씀 |
| `aux_priv` MLP 512→256→383 | 학습 전용 | 해석용 중간값, 채점 입력 후보 |
| `core_skip` h' = h + Linear(x_in) | 헤드·value·aux가 읽음 | 세계 모델 입력은 h'로 함 |
| 덤프 도구 `python -m uranium diag dump` | 몸통 + 행동 종류 헤드만 도는 `action_seq` 경로 | 6절 시험의 덤프에 거의 그대로 씀 |
| DAgger shard `memory_action`(040-R22) | 모델이 **실제로 둔 결정** 기록 | 세계 모델의 행동 조건으로 가장 깨끗한 데이터 |

### 1.9 조사(2026-11-08) 결론을 다시 보면

## 2. 무엇을 두고 계획하나

### 2.1 후보 세 가지

| | (a) 행동 종류만 | (b) 매크로 결정(옵션) | (c) 전체 행동을 정책에서 뽑기 |
|---|---|---|---|
| 후보 | 지금 결정의 행동 종류. 101개 중 `type_mask`가 연 것, 실제로는 정책 상위 m개(m = 4~8) | 몇 초~수십 초에 걸친 결정 8~12개: 벙커, 배럭 추가, 서플라이, 앞마당, 정제소, 팩토리, 아카데미, SCV 생산, 정찰, 공격, 방어·홀드, "운영 없음" | 정책에서 K개(K ≈ 16~20) 전체 행동(종류·지연·선택·대상·위치)을 뽑음 |
| 세계 모델 조건 | 행동 종류 임베딩(+ 지연 bucket) | 옵션 임베딩 | `ar`(행동 임베딩) + 대상·위치 임베딩(거친 격자) |
| 후보 수 | 4~8 | 8~12 | 16~20 |
| 정책 변경 | 없음. 고른 종류로 나머지 헤드만 이어 샘플 | **있음**: 옵션을 실행할 정책이 옵션을 입력으로 받아야 함(z와 비슷한 조건 입력, 헤드 파인튜닝) | 없음 |
| 레이블 | 이미 있음(shard 행동 레이블, `memory_action`) | 규칙으로 새로 만들어야 함(아래) | 이미 있음 |
| 장점 | 가장 단순. 건물·생산 행동은 그 자체가 결과가 긴 "옵션"이라 의미가 있음 | 계획 단위가 전략 수준이라 8·32 결정 뒤 차이가 큼 | 위치(벙커 자리)·대상까지 고름 |
| 단점 | 이동·공격처럼 한 결정의 효과가 작은 행동은 구별이 안 됨 | 레이블 규칙이 정책·전략 판단을 담음, 정책 재학습 필요 | 위치·선택의 효과를 맞히려면 데이터가 훨씬 많이 필요, 후보 대부분이 서로 비슷함 |
| 크기(예측기, k마다) | 약 100만 파라미터(3.2 출력 포함, 모델 2의 약 4%) | 비슷 | 약 110만 파라미터 + 위치 임베딩 |

### 2.2 (a)를 권하는 이유와 (b)·(c)의 자리

- **(a)가 첫 단계입니다.**
  - 행동 종류를 조건으로 주고 "그 뒤는 정책이 평소대로 둔다"고 가정한 예측은 표준적인 Q^π 형태입니다. 모델이 직접 둔 판으로 학습하면 "그 뒤"가 바로 우리 정책입니다.
  - 운영 행동(건설 12종, 애드온 6종, 생산 14종, 연구 11종, 업그레이드 15종, 이·착륙, 취소)은 실행되면 결과가 수십 초 이어집니다. 그래서 행동 종류 하나가 사실상 옵션입니다.
  - 이동·공격 같은 결정은 계획 대상에서 빼고, 계획 모듈을 켜는 조건(트리거)을 "정책 상위 후보에 운영 행동이 있을 때"로 둡니다(4.4).
- **(b)는 분석·트리거 레이블로 먼저 씁니다.** 정책을 옵션 조건으로 바꾸는 일은 헤드 파인튜닝이라 BC 재학습에 가깝습니다. 6절 시험의 "행동 종류 묶음 조건(오라클)" 결과가 크게 나오면 그때 다시 검토합니다.
  - 레이블 규칙 예(기본안(미확정)): 창 [t, t+32) 안의 첫 운영 행동 종류(Build_X → "X 건설"), `Attack_Pos`·`Attack_Unit` 대상이 적 진영 절반이면 "공격", 아군 본진·앞마당 근처 `Hold`·`Attack_Pos`이면 "방어", SCV·마린이 적 시작 위치 쪽으로 `Move_Pos`이면 "정찰", 없으면 "운영 없음". 위치 판정은 맵 사전계산(`base_loc`, 시작 위치)으로 합니다.
- **(c)는 위치·선택이 중요한 순간(벙커 자리, 첫 정찰 SCV)용 확장입니다.** AlphaStar Unplugged가 뿌리에서만 전체 행동을 임베딩하고 아래 노드는 행동 종류·지연만 예측한 방식과 같습니다. 행동 임베딩은 `ar`을 재사용합니다.

## 3. 세계 모델이 무엇을 맞히고 후보를 어떻게 채점하나

### 3.1 세 가지 예측 대상

| | (i) 인코더 요약 y + 학습한 채점기 | (ii) 코어 잠재 h-공간 동역학 | (iii) privileged 예측(해석용 중간값) |
|---|---|---|---|
| 정답 | y_{t+k} = LN([e_pool, s_pool]), stop-grad (지금 JEPA 정답) | h'_{t+k}, stop-grad | p_{t+k}(적 실제 상태 383차원) |
| 채점 | ŷ 위의 새 채점 헤드 | 기존 가치 헤드(win_open, value)를 ĥ에 그대로 | p̂를 value의 privileged 자리에, 또는 사람이 읽는 규칙 |
| 장점 | 지금 손실·정답을 그대로 씀. 붕괴 감시(`jepa_tgt_std`)도 있음 | 기존 헤드 재사용, 깊이 2 이상으로 넓히기 쉬움(MuZero·EfficientZero) | 사람이 읽을 수 있음("적 저글링 12 예상"), Defogger 선례 |
| 단점 | y는 사람이 못 읽음. 채점기를 새로 학습해야 함 | 기존 실전용 가치(win_open)가 약함. h'는 GTrXL 기억·바깥 LSTM 상태 전체가 아니라 굴리기 어려움 | 적 상태는 우리 행동에 크게 안 바뀜(k = 8에서). 실전 사용은 원칙 질문(1.3) |
| 문헌 | SPR, V-JEPA 2-AC(요약 공간 거리), DINO-WM | MuZero(가치·보상·정책 일관성), EfficientZero(시간 일관성 손실) | Defogger(브루드워) |

### 3.2 권장 형태: 공유 몸통 하나에 출력 여러 개

```
입력: h'_t(512) ⊕ Emb(a)(32) [⊕ Emb(delay)(16)] ⊕ Emb(k)(16)
몸통: MLP 576 → 512 → 512 (ReLU) = ĥ_{t+k}
출력:
  ŷ_{t+k}   (512)  1 − cos   ← (i) 지금 JEPA 정답
  p̂_{t+k}   (383)  MSE        ← (iii) privileged, 있는 행만
  ô_{t+k}   (~10)  MSE        ← 내 상태: SCV 수, 서플라이, 건물 종류별 수, 병력 수(입력 스칼라에서 바로 계산, 자기 시야)
  q̂_k       (1~3)  BCE/MSE    ← 채점 대상(8절 1번): 판 결과, 또는 8:00 SCV ≥ 8 같은 초반 생존 지표
  [선택] ĥ  cos(ĥ, h'_{t+k}) ← (ii) 기존 헤드 재사용·깊이 2용
```

- 이유
  - (i)만으로는 채점이 안 되고, (ii)만으로는 기존 가치가 약하고, (iii)만으로는 우리 행동의 효과가 잘 안 보입니다. 함께 학습하면 서로 보조 신호가 됩니다.
  - **내 상태 출력 ô는 가장 싼 정상 동작 확인입니다.** "Build_Bunker를 고르면 32 결정 뒤 벙커 수 예측이 오른다"가 안 되면 나머지도 믿을 수 없습니다.
  - AlphaStar Unplugged의 MuZero Supervised는 탐색 없이도 BC보다 나았고(very_hard 상대 92% 대 88%), 저자들은 이를 가치 학습과 잠재 모델의 정규화 효과로 봤습니다. 풍부한 예측 대상이 채점 학습을 돕는다는 쪽의 근거입니다(분리 실험은 없음).
- k마다 따로 둘지(지금 g_k처럼), k 임베딩 하나로 공유할지는 6절 시험에서 둘 다 볼 필요는 없습니다. 시험은 k마다 따로 두는 단순한 쪽으로 합니다.

### 3.3 한 번에 건너뛰기(k = 1·8·32) 대 굴리기

| | 건너뛰기 f_k(h_t, a) | 굴리기 h → h → … (MuZero식) |
|---|---|---|
| 오차 | k마다 한 번의 오차 | 단계마다 쌓임(V-JEPA 2-AC가 밝힌 한계) |
| 중간 행동 | "그 뒤는 정책대로"로 평균냄 | 단계마다 행동을 줘야 함 → 중간 노드마다 정책 사전분포가 필요 |
| 상상한 상태의 정책 | 필요 없음(깊이 1) | 필요함. 그런데 행동 종류 헤드는 h만이 아니라 c(스칼라 문맥)와 유닛 토큰 E(우회로)를 읽음 → 상상한 상태에는 c·E가 없음 → **ĥ만 보는 별도 사전분포 헤드가 필요**(AlphaStar Unplugged가 아래 노드에서 행동 종류·지연만 예측한 이유와 같음) |
| 실시간 비용 | 후보 m개 × k 3개 = MLP 24행, 1 ms 안팎(추정) | 시뮬레이션마다 동역학 + 사전분포, 50회면 수십 ms(추정) |
| 권장 | **첫 단계** | 깊이 2(우리 행동 → 상대 반응)가 필요하다고 드러날 때 |

- 상대 반응은 건너뛰기 예측 안에 평균으로 들어갑니다. 상대가 확률적으로 반응하는 것을 따로 다루려면 Stochastic MuZero의 우연 노드가 필요합니다. 첫 단계 범위 밖입니다.

### 3.4 채점 대상의 어려움

- **판 결과는 멀고 시끄럽습니다.** 판 길이 중앙값이 약 16분이고, 승패를 시작 위치가 크게 가릅니다(`checkpoint1_rl.md`). 2:40의 결정 하나가 판 결과 예측을 바꾸는 폭은 작을 것입니다.
- **초반 생존 지표는 빠르게 반응하지만 편향이 있습니다.** 예: 8:00 SCV ≥ 8(042 러시 점검의 막음 판정), 4:30 전 벙커 완성(G0에서 막은 판과 진 판을 가른 것). 이것만 채점하면 지나치게 수비적인 선택(헛벙커)을 좋게 볼 수 있습니다.
- 그래서 채점 대상은 사용자 결정입니다(8절 1번). 기본안(미확정): 판 결과와 초반 생존 지표를 함께 맞히고, 후보 채점은 "판 결과 예측 + 작은 가중치 × 생존 지표"로 합니다. 6절 시험은 두 대상을 따로 보고합니다.

### 4.2 권장: (A)를 주 경로로

- **사용자의 목표(결정에 쓰기)에 직접 맞습니다.**
- **계보를 건드리지 않습니다.** 몸통은 고정이고, 계획 모듈은 추론 때만 켭니다. 같은 체크포인트·같은 seed로 켬/끔 짝 비교가 됩니다(050 프로토콜과 같은 방식).
- **스타2 선례가 정확히 이 형태입니다.** AlphaStar Unplugged는 학습 때 MCTS를 쓰면 붕괴했고, 추론 때만 쓴 탐색은 항상 탐색 없는 쪽보다 나았다고 보고했습니다.
- **우리 약점과 맞습니다.** RL 정체의 원인 하나가 "필요한 방어 행동이 정책 분포에서 드묾"입니다. 재정렬은 정책이 이미 후보로 올린 드문 행동의 확률을 필요할 때 올립니다.
- (B)는 (A)의 세계 모델이 6절·대전 검증을 통과한 뒤의 두 번째 단계입니다. 그때는 계보와 분리된 비교 run으로 합니다. 이유는 학습 처리량 여유(1.7절)가 있어 actor 쪽 계획 비용이 싸고, 계획이 고친 정책 π'를 목표로 증류하면 실전에서 계획 없이도 일부 이득이 남기 때문입니다.
- (C)는 지금 권하지 않습니다. 이산·자기회귀 행동과 실시간 조건에 맞지 않고, 목표 조건 정책은 재학습이 필요합니다. 우리 모델의 z가 이미 목표 조건 역할을 합니다.

### 4.3 (A)의 한계를 미리 적어 둠

- 깊이 1이라 "상대가 이렇게 받으면"을 따로 보지 않습니다. 평균만 봅니다.
- 정책이 상위 후보로 올리지 않은 행동은 고르지 못합니다(의도한 안전장치이기도 함). 벙커 확률이 0.001이면 후보에 안 듭니다. 그래서 트리거가 "위협 감지"일 때는 운영 행동 몇 개를 강제로 후보에 넣는 선택지가 있습니다(8절 3번).
- 실전용 채점이 약하면 이득이 없습니다. 6절 M3가 이 위험을 먼저 잽니다.

### 4.4 (A)의 구체 모습(설계 아님, 판단을 위한 그림)

1. **평소처럼 몸통을 돈다**: h'_t, c, E, 행동 종류 로짓 ℓ(마스크 적용).
2. **트리거 판정**(기본안(미확정))
   - 정책 상위 m개 안에 운영 행동 종류가 있고 그 확률 ≥ ε, 또는
   - 게임 6:00 전이고 적 병력이 본진·앞마당 근처에 보임(관측 스칼라에서 계산, 자기 시야)
   - 트리거가 아니면 지금과 똑같이 샘플합니다(비트 동일).
3. **후보**: Gumbel-top-m(ℓ에 Gumbel 잡음을 더한 상위 m개, 중복 없음). m = 4~8.
4. **채점**: 후보마다 f_k(h'_t, a)를 k = 8·32로 계산하고 q̂(a)를 얻습니다. 앙상블 3개의 평균 − β·표준편차로 비관적으로 채점합니다(채점기 착취 완화).
5. **정책 개선**: Gumbel MuZero 방식. 선택 = argmax_a [g(a) + ℓ(a) + σ(q̂(a))], σ는 단조 증가 척도 변환(c_scale로 세기 조절). 후보가 m ≤ 8이고 깊이 1이라 Sequential Halving 없이 모두 한 번씩 평가합니다.
6. **나머지 헤드**: 고른 행동 종류를 고정하고 지연·선택·대상·위치를 지금처럼 샘플합니다(헤드 forward가 이미 레이블 주입을 지원하므로 "행동 종류만 주입" 경로를 더함).
7. **기록**: 트리거 비율, 정책 선택과 달라진 비율, 후보 수, q̂ 폭, 추가 지연(p50·p99). 세션 기록과 RL behaviour log-prob(B 단계에서 V-trace가 쓰는 것은 π가 아니라 실제로 뽑은 π')에 남깁니다.

- **비용(추정)**: 트리거 행에서 MLP 576→512→512→(출력) × 앙상블 3 × 후보 8 × k 2 = 48행. CUDA 그래프 캡처로 1 ms 안팎, Linux ROCm은 수 ms로 봅니다. 6절 다음 단계에서 잽니다.
- **RL actor·평가에서도 같은 코드로 켤 수 있습니다.** lockstep이라 시간 제한이 없습니다.

### 6.4 측정

예측기는 모두 같은 구조(MLP 입력 → 512 → 512, ReLU, 출력 3.2의 ŷ·p̂·ô·q̂), 같은 학습 step·같은 seed입니다. 판 단위 bootstrap 95% 신뢰구간을 붙입니다.

| 이름 | 입력 | 뜻 |
|---|---|---|
| U | h'_t | 행동 없는 기준선(지금 JEPA와 같은 정보) |
| A | h'_t ⊕ Emb(a_t) | 행동 종류 조건 |
| A+d | h'_t ⊕ Emb(a_t) ⊕ Emb(지연) | 지연까지 |
| H(오라클) | h'_t ⊕ [t, t+k) 행동 종류 비율(101) | "앞으로 할 일을 다 안다"의 상한. (b) 옵션의 가치를 가늠 |
| S(대조) | h'_t ⊕ Emb(같은 판의 무작위 행 행동) | 입력이 늘어난 효과만 |

- **M0 기초**(판정에 안 씀, 설계 수치용)
  - 행마다 열린 행동 종류 수 분포
  - 정책 상위 m(4·8·16)개의 확률 합
  - k = 8·32 쌍의 실제 프레임 간격 분포(1.2절의 결정 간격 불일치를 여기서 정리)
  - 운영 행동 행의 비율(운영 행동 = 건설·애드온·생산·연구·업그레이드·이착륙·취소)
- **M1 조건 이득**: 평가 판에서 L_U − L_A(ŷ 1 − cos, p̂ R², ô R², 판 결과 NLL)를 k마다, 전체 행과 **운영 행동 행**으로 나눠 봅니다. 오라클 대비 몫 r = (L_U − L_A) / (L_U − L_H)도 씁니다.
- **M2 구별**: 운영 행동 행에서 후보 C_t = 정책 상위 8개(열린 것) ∪ {a_t}.
  - M2a 폭: 후보 예측끼리의 평균 거리 D_t / 실제 행동 예측의 오차 RMS N. 중앙값 R = D/N.
  - M2b 방향: 후보가 Build_X일 때 32 결정 뒤 X 수 예측 ô_X가 Build_X 아닌 후보보다 큰 행의 비율. 생산(Train_X)도 같은 방식.
- **M3 채점**
  - M3a 결과 순위: 판 결과(무승부 제외) AUC를 비교합니다. q̂_A(h'_t, a_t), q̂_U(h'_t), win_open(h'_t), 그리고 오라클 q̂_U(h'_{t+k})(실제 미래 상태). 시간대 2~4·4~6·6~10분으로 나눕니다.
  - M3b 러시 정상 확인: 교사 보관분·모델 판의 저그 상대 2:00~3:30 행 중 Build_Bunker가 열린 행. ΔQ = q̂(h, Bunker) − Σ_c π(c) q̂(h, c). 러시 판 평균 ΔQ − 운영형 판 평균 ΔQ와 그 신뢰구간, 행 단위 AUC(ΔQ로 러시·운영형 가르기). 채점 대상 두 가지(판 결과, 8:00 SCV ≥ 8)를 따로.
  - M3c 착각 점검: 같은 M3b를 사람 데이터로만 학습한 예측기와 모델 판으로만 학습한 예측기로 따로 계산합니다. 사람 쪽만 러시 판에서 ΔQ < 0(벙커를 나쁘게 봄)이면 착각입니다.
  - M3d advantage 일치: 운영 행동 행에서 Â_t = q̂(a_t) − Σ_c π(c) q̂(c)와 실현값 G_t = (결과) − q̂_U(h'_t)의 순위상관.

### 6.7 사전 예상(시험 전, 2026-11-11)

- M1: 전체 행 평균 이득은 아주 작을 것입니다(대부분 이동·공격·채취라 한 결정의 효과가 작음). 운영 행동 행에서는 내 상태 ô와 ŷ에서 k = 32 이득이 보일 것입니다. 판 결과 NLL 이득은 거의 없을 것입니다.

## 8. 사용자 결정이 필요한 것

1. **무엇을 "좋은 결과"로 채점할까요?**
   - 상황: 계획 모듈은 후보 행동마다 "이걸 하면 결과가 좋아질까"를 숫자로 매깁니다. 그 숫자가 무엇을 뜻할지 정해야 합니다.
   - 예: 2:40에 적 앞마당이 안 보이고 저글링이 먼저 보였습니다. 벙커를 지을까요?
     - "판을 이길 확률"로 매기면 맞는 기준이지만, 이 결정 하나로 바뀌는 폭이 작고 시작 위치에 묻혀 잘 안 보일 수 있습니다.
     - "8분에 SCV가 8기 이상 살아 있을 확률"로 매기면 러시 방어에는 빠르게 반응하지만, 러시가 아닌 판에서도 벙커를 좋게 볼 위험이 있습니다(헛벙커).
     - 둘을 섞으면 중간이고, 섞는 비율을 정해야 합니다.
   - 기본안(미확정): 판 결과를 주로, 초반 생존 지표를 작은 가중치로 섞음. 6절 시험은 둘을 따로 보고합니다.
2. **계획 모듈이 언제 끼어들까요?**
   - 상황: 매 결정마다 켜면 비용·위험이 크고, 효과도 대부분 이동·공격 결정이라 작습니다.
   - 예: (가) 정책이 건물·생산을 고려할 때만 (나) 6분 전 적 병력이 기지 근처에 보일 때도 (다) 늘.
   - 차이: (가)는 가장 안전하고 싸지만 위협이 와도 정책이 운영 행동을 안 떠올리면 안 켜집니다. (나)는 러시 방어를 겨냥합니다. (다)는 비용과 착취 위험이 큽니다.
   - 기본안(미확정): (가) + (나).
3. **계획 모듈이 정책을 얼마나 뒤집을 수 있을까요?**
   - 상황: 정책이 "마린 생산 60%, 벙커 2%"라고 할 때, 계획이 벙커를 좋게 보면 어디까지 바꿀지입니다.
   - 예: (가) 정책 상위 몇 개 안에서만 순서를 바꿈 (나) 위협 순간에는 정책이 거의 안 고르는 운영 행동(벙커 등)도 후보에 강제로 넣음 (다) 열린 행동 전부를 후보로.
   - 차이: (가)는 안전하지만 정책이 놓친 행동은 못 살립니다. (나)는 러시 방어에 직접 듣지만 채점이 틀리면 헛벙커가 늘 수 있습니다. (다)는 채점기 착취 위험이 가장 큽니다.
   - 기본안(미확정): (가), 시험 결과(M3b)가 좋으면 (나)를 비교.
4. **세계 모델을 무엇으로 학습할까요?**
   - 상황: 사람 리플레이는 양이 많지만, 사람이 어떤 행동을 한 이유가 우리 모델이 못 본 단서일 때 "그 행동 = 그 상황"으로 잘못 배웁니다. 우리 모델이 직접 둔 판은 이 문제가 적지만 양이 적습니다.
   - 예: 사람은 지어지는 풀을 보고 벙커를 짓습니다. 모델이 그 단서를 못 읽으면 "벙커를 지으면 진다"고 배울 수 있습니다.
   - 선택: (가) 사람 + 모델 판 함께 (나) 모델 판 위주, 사람은 표현 학습 보조로만 (다) 모델 판만.
   - 기본안(미확정): 6절 M3c 결과를 보고 정함. 그 전에는 (가)로 시험.
   - 함께 정할 것: 계획 켬/끔 대전에서 "좋아졌다"고 볼 기준(예: 러시 점검 막음 합, T0 세 종족 승률, 회귀 게이트 050-R10 통과).
5. **"적 상태 추정값"을 실전 채점에 써도 될까요?**
   - 상황: 11-09 결정으로 적의 실제 상태(privileged)는 학습 때 정답으로만 씁니다. 세계 모델은 자기 시야만 보고 "적 저글링이 대략 12마리일 것"이라고 추정할 수 있습니다. 이 추정을 실전에서 후보 채점에 쓸지입니다.
   - 차이: 쓰면 적 상황을 반영한 채점이 됩니다. 추정은 자기 시야의 함수라 맵핵은 아니지만, 숨은 정보로 학습한 값을 실전 판단에 쓰는 것이라 원칙 해석이 필요합니다. 안 쓰면 추정은 해석·디버깅용으로만 남습니다.
   - 기본안(미확정): 시험·S1에서는 해석용으로만, 실전 채점 입력으로는 쓰지 않음.
6. **실전(SC:R)에도 켤까요, 추가 지연은 얼마까지 허용할까요?**
   - 상황: 지금 명령은 관측 뒤 2~3프레임에 처리됩니다. 계획이 지연을 더하면 그만큼 늦어집니다.
   - 선택: (가) OpenBW 평가에서만 먼저, 실전은 나중 (나) 실전도 켬, 추가 지연 p99 ≤ 1프레임(약 42 ms) 같은 기준.
   - 기본안(미확정): (가). 실전은 S2 대전 결과 뒤.
7. **나중에 RL 학습에도 쓸까요?**
   - 상황: 계획이 고른 행동을 RL 목표로 삼으면 실전에서 계획 없이도 이득이 일부 남습니다. 대신 RL run이 계보와 달라집니다.
   - 선택: (가) 결정 순간에만 쓰고 RL은 지금 그대로 (나) S2 통과 뒤 계보와 분리된 비교 run으로 시험.
   - 기본안(미확정): (나), 모델 2 RL 판정(042-R21 ④) 뒤.
8. **시험을 언제, 어느 장비에서 할까요?**
   - 상황: CUDA 호스트는 `m2-s1e2`(11-12 새벽까지 예상) 중이고, Linux ROCm 호스트는 경로 측정 중입니다.
   - 선택: (가) `m2-s1e2`가 끝난 뒤 CUDA 호스트 빈 시간에 1~2시간 (나) Linux ROCm 호스트 하나가 빌 때 표본을 줄여 3~5시간 (다) 모델 2 계보가 BC 기준선(`m2-s2e2`)에 이를 때까지 미룸.
   - 기본안(미확정): (가). 예측기 학습·분석은 Linux CPU 호스트.
