# 후속 검토 — 변형이 세 약점을 보완하지 못한 이유는 무엇인가

- 작성: 2026-10-27, 독립 리뷰어(Claude, Fable 5.1 high, 사용자 후속 질문). 앞 리포트 [`m6_arch_ablation_review.md`](m6_arch_ablation_review.md)와 같은 규칙(읽기 전용, 사실/가설 구분, 확신도 표기). 메인 세션 확인: 학습기가 묶음마다 코어·바깥 LSTM 상태를 모두 detach한다(`python/uranium/bc/trainer.py` 176행, `net.detach_state`). 이 한계는 spec 032 §2.7 위험 항목에 이미 적혀 있었다.
- 새로 계산한 것: 같은 step(= 같은 batch)끼리 짝지은 **헤드별 학습 손실 차이**를 1,000 update 창마다 구했다(`paired_loss.py`). 데이터 순서가 같으므로 두 run의 같은 step 손실 차는 순수하게 모델 차이다. 기준은 두 가지다: 진짜 기준 GTrXL(이 호스트 로그에 0~6,048만 있음), 그리고 끝까지 로그가 있는 terrain(기준과 구조·결과가 가장 가까운 run, 기준 대신 쓴 참조). 아래에서 "−"는 변형이 더 잘 맞춘다는 뜻이고, 비율은 그 헤드의 손실 수준(행동 1.04, delay 1.90, 선택 3.38, 대상 유닛 0.22, 위치 3.26) 대비다.

## 0. 요약

| 약점 | 변형 | 모방(학습·val)에서 보인 효과 | 대전에서 보인 효과 | 보완 못 한 주된 이유 (판단) |
|---|---|---|---|---|
| ① 요약 병목(평균 두 개) | pool | **반대 방향**: 요약에 의존하는 행동·delay 손실이 기준보다 0.6~0.9% 나쁨, 간격은 줄어드는 중 | 무승부 최저(36%)·결판 승률 최고(56%)지만 잡음 범위, 대 T0 테란 최악(15승 56패) | (나) 새 모듈(학습되는 질문 8개)이 10,000 update에서 평균 요약의 강한 사전 지식을 아직 못 따라잡음 + (다) 개수 자체는 이미 스칼라 feature에 있고, 개수·구성이 결과를 가르는 결정(교전 시점)은 전체 step의 극소수라 NLL과 지금의 승패에 거의 안 걸림. 데이터 부족(가)은 아님 |
| ② 늦은 결합(지형·스칼라) | ctx / terrain | **ctx는 예측대로 작은 진짜 효과**: 토큰에 의존하는 선택 −0.8%, 대상 유닛 −2.7%, 위치 −1%가 2,000 update부터 안정적으로 유지. **terrain은 반대**: 같은 헤드들이 +0.5~1% 나쁨, 간격은 줄어드는 중 | ctx 중위(무승부 44%), terrain 리그 2위·T0 1위(둘 다 잡음 범위) | 스칼라 쪽은 병목이 맞지만 크기가 1% 수준이라 (평가) 대전 해상도(쌍당 100판 ≈ ±27 Elo) 아래. 지형 쪽은 (다)+(설계): 좌표·맵 채널로 이미 충분하고 원시 채널 10개를 토큰에 더하는 방식이 초반엔 잡음으로 작용 |
| ③ 장기 상태 없음 | outer | **가장 큰 효과이고 아직 커지는 중**: 행동 −0.5%(1k) → −1.8%(9k), delay −0.4%, 선택 −0.4%, 위치 −0.5% | 수동적(무승부 43%, 결판 승률 46%), T0 최하 13% | (설계·학습 방식) **이번 실험은 장기 기억을 시험할 수 없었다**: 묶음(64 step) 사이 상태를 끊어 학습하므로 바깥 LSTM은 64 step(게임 약 30초) 밖의 정보를 기억하도록 배울 길이 없다. 관측된 이득은 "32 step 평균을 토큰·맵·코어에 되돌리는 두 번째 경로"에서 온 것으로, 장기 기억과 무관. 장기 기억이 지금 병목인지는 측정된 바 없음 |

세 약점 공통:
- **(가) 데이터 부족은 아니다.** 어떤 run도 데이터를 한 번도 다 보지 못했다(10,000 update가 본 게임 약 8,500개, S1 한 epoch 33,183 시점의 26%). 데이터가 모자라서 못 배운다는 말은 한 epoch을 넘긴 뒤에나 할 수 있다. 지금 단계에서 (가)와 (나)는 같은 말이고, 그중 작동하는 것은 (나)다.
- **(나) 학습량**은 ①·③의 모듈 쪽 원인으로 맞다(간격이 아직 움직이는 중: pool은 줄어들고, outer·all은 벌어진다). 다만 ②(ctx)는 2,000 update에서 이미 안정됐으니 학습량 문제가 아니라 효과 크기 자체가 1%다.
- **(다) "지금 결과에 의미가 없다"**가 대전 결과에 대해서는 가장 큰 이유다. 대전의 승패는 (i) 초반 러시 생존(T0 패배의 66~80%가 12분 이전)과 (ii) 기운 판 마무리(무승부의 72%가 한쪽 항복 판정 상태)로 갈리는데, 둘 다 세 약점과 직접 관련이 없다. 초반 방어는 눈앞의 적(64 step 안, 토큰에 있음)에 반응하는 문제이고, 마무리는 보이는/기억된 건물을 찾아 부수는 문제다. 둘 다 사람 리플레이에 드문 장면(BC 커버리지)과 온도 1 샘플링(정책의 흐릿함)에 묶여 있다.
- **(평가)** 모방 쪽 효과 1~3%는 쌍당 100판·300판 대전으로는 보일 수 없는 크기다(앞 리포트 2절).

읽는 법(사실, 확신 높음 — 같은 batch 비교라 데이터 순서 잡음이 없고 창마다 1,000개 step을 평균했다):
- **ctx**: 토큰에 의존하는 세 헤드(선택·대상 유닛·위치)가 일관되게 좋아졌고(선택 −0.8%, 대상 유닛 −2.7%, 위치 −0.9%), **2,000 update 이후 크기가 변하지 않는다.** val에서도 같은 방향(대상 유닛 NLL 2.151 대 기준 2.177, 위치 5.684 대 5.715).
- **terrain**: 같은 세 헤드가 기준보다 **나쁘다**(2k–3k 위치 +0.9% → 5k–6k +0.4%, 줄어드는 중). val도 같은 방향(대상 유닛 2.209로 7개 중 최악, 위치 오차 중앙 5.0 대 4.47). 지형을 토큰에 더하는 것이 적어도 이 길이에서는 해가 됐다.
- **pool**: 요약에 의존하는 행동·delay가 **나쁘다**(행동 +1.1% → +0.6%, delay +0.5% → +0.3%, 줄어드는 중). 토큰 헤드는 아주 조금 좋다(−0.1~−1%). val도 같은 방향(행동 NLL 1.040 최악).
- **outer**: 행동 손실 이득이 **1k에서 −0.5%, 9k에서 −1.8%로 계속 커진다.** delay·선택·위치도 −0.4~−0.5%. 7개 중 유일하게 간격이 뚜렷이 벌어지는 중이다(all도 outer를 포함해서 같은 모양).
- **lstm**: 행동 간격이 +1.3%(1k) → +0.2%(9k)로 **거의 사라지고**, 선택·위치는 처음부터 LSTM이 더 좋다(−0.4%). 앞 리포트 3.2절(LSTM은 수렴이 조금 늦을 뿐)과 맞는다.

### 1.3 보조 사실
- 결정 빈도는 분당 124~149회(대전 기록 중앙)다. 따라서 코어의 64 step은 **게임 시간 약 26~31초**, 이전 기억을 거친 최대 128 step은 약 1분이다.
- 관측(030 §4 스칼라)에는 이미 **유닛·건물 개수(완료·건설 중·적 최대 관측·적 보유·적 생산 중)가 ln(1+n)/4로 들어 있다.** "평균은 개수를 모른다"는 지적은 e_pool 하나만 보면 맞지만, 모델 전체는 개수를 스칼라로 받는다. e_pool이 잃는 것은 개수가 아니라 **구성·배치·소수 유닛의 종류**다.
- 장기 정보는 AgentMemory가 규칙으로 들고 간다: 기억된 적 건물(엔티티로 포함), 적 최대 관측 수(스칼라), 타일별 마지막 시야 시각(`last_seen_age` 맵 채널). 코어 밖의 장기 정보가 전혀 없는 것은 아니다.
- 학습기는 묶음(B 32 × T 64)마다 코어 상태와 **바깥 LSTM 상태를 모두 detach**한다(`python/uranium/bc/trainer.py` 175~176행, `net.detach_state`가 outer 상태도 포함). spec 032 §2.7에 적힌 대로다. 바깥 LSTM은 묶음 안에서 **딱 한 번(step 32)** gradient가 흐르는 갱신을 받는다.
- 10,000 update가 본 게임: 8,486개(terrain run 로그 `games`), 그중 결과 없는 게임 1,580개. S1 한 epoch 33,183 시점의 26%. 어떤 run도 같은 게임을 두 번 보지 않았다.

## 2. 약점별 판단

### ① 요약 병목 (e_pool 평균 두 개) — 변형 pool

**무엇이 관측됐나**: attention 요약은 그것이 고치려던 헤드(행동·delay)를 **더 못 맞춘다**(10k 시점 +0.6%, 줄어드는 중). 대전에서는 무승부가 가장 적고 결판 승률이 가장 높지만(앞 리포트) 잡음 범위이고, T0 테란에는 가장 많이 졌다(56패).

**판단**(확신 중간):
- **(가) 아니다.** 유닛이 많은 장면은 모든 게임의 중·후반에 있고, 8,500게임이면 수십만 step이다. 장면이 모자라서가 아니다. (장면 비율 자체는 shard를 읽어야 셀 수 있어 이번에 계산하지 못했다 — 아래 측정 제안 B.)
- **(나) 맞다, 모듈 쪽으로.** 평균 요약은 파라미터가 없고 처음부터 "무난한" 요약을 준다. 학습되는 질문 벡터 8개는 무작위 초깃값에서 시작해 무엇을 물을지부터 배워야 한다. 간격이 줄어드는 중이라는 것이 "아직 따라잡는 중"이라는 직접 증거다. 더 길게 배우면 **같아질** 가능성은 높고, **넘어설지는** 알 수 없다.
- **(다) 상당 부분 맞다.** 두 가지 뜻에서. (i) 개수는 이미 스칼라 feature로 들어가므로 "개수를 모른다"는 병목은 원래 없었다. 남는 것은 구성·배치·소수 유닛인데, 그것이 결정을 바꾸는 장면(다크템플러 1기를 보고 디텍터를 뽑는다, 적 병력 구성을 보고 교전을 피한다)은 사람 데이터에서 드물고 NLL에서 차지하는 무게가 작다. (ii) 지금 대전의 승패는 초반 러시 생존과 마무리에서 갈리는데, 둘 다 요약 품질보다 "눈앞의 적에 바로 반응하는가"와 "건물을 끝까지 찾아가는가"의 문제다.
- **(BC의 한계)** 요약이 좋아져도 그 정보를 **써야 할 결정**이 라벨에 드물면 BC는 배울 신호가 없다. 교전 판단은 RL에서 보상으로 배우는 것이 자연스럽다. 이 약점은 RL 단계에서 다시 중요해질 수 있다(가설).
- pool이 대전에서 더 결단력 있어 보이는 것은 "적 구성을 보고 공격 시점을 안다"일 수도, 단순히 다른 분포(온도 1 샘플링에서 공격 행동이 더 자주 뽑힘)일 수도 있다. 지금 자료로는 가를 수 없다(측정 제안 B·D).

### ② 늦은 결합 (토큰이 지형·스칼라 문맥을 모름) — 변형 ctx, terrain

**무엇이 관측됐나**: 스칼라 토큰(ctx)은 예측대로 토큰 헤드를 좋게 했다(선택 −0.8%, 대상 유닛 −2.7%, 위치 −0.9%), 2,000 update부터 안정. 지형(terrain)은 같은 헤드를 나쁘게 했다(줄어드는 중). 대전에서는 ctx가 중위, terrain이 상위지만 둘 다 잡음 범위다.

**판단**(스칼라 쪽 확신 높음, 지형 쪽 중간):
- **스칼라 문맥은 작지만 진짜 병목이었다.** 효과가 일찍 나타나 유지되는 것은 "쉽게 배우는 진짜 신호"의 모양이다. 보완되지 않은 게 아니라 **보완됐는데 크기가 1~3%**다. 이 크기는 (평가) 대전에서 보일 수 없다(100판 ≈ ±27 Elo). (가)(나)(다) 모두 아니다 — 굳이 고르면 (평가).
- **지형은 지금 단계에서 병목이 아니다(다).** 토큰은 좌표를 갖고 있고, 맵 채널 인코더가 지형을 따로 보며, 학습 맵이 290개라도 사람 리플레이의 선택·대상 결정이 높낮이·길목에 좌우되는 비율은 작다. 원시 채널 10개를 선형 투영해 토큰 입력에 **더하는** 방식은 초반에 토큰 표현을 흔드는 잡음이 됐다(설계·구현 방식). 간격이 줄어드니 길게 배우면 해가 사라질 것이고 득이 될지는 불명.
- terrain이 대전에서 좋게 나온 것(T0 20.8%, 리그 2위)을 지형 덕으로 보기엔 모방 지표가 반대 방향이다. 잡음으로 본다(확신 중간).

### ③ 장기 상태 없음 (코어 64 step, 공유 장기 상태 없음) — 변형 outer

**무엇이 관측됐나**: 바깥 LSTM은 7개 중 가장 큰 모방 이득을 보였고(행동 −1.8%) 그 이득이 **아직 커지는 중**이다. 그러나 대전에서는 수동적이고(무승부 43%) T0 승률 최하(13%)다.

**판단**(확신 높음 — 구조적 이유):
- **이번 실험은 ③을 시험하지 못했다(설계·학습 방식).** 묶음 사이에서 바깥 상태를 detach하므로 gradient는 64 step 안에서만 흐른다. 바깥 LSTM이 "3분 전에 본 것"을 기억해 두는 것이 도움이 되더라도, 그 도움은 손실에 gradient로 연결되지 않아 배울 수 없다. 배울 수 있는 것은 "직전 32 step의 코어 출력 평균을 토큰·맵·코어 입력에 되돌리면 다음 32 step 예측이 좋아진다"는 것뿐이다. 즉 관측된 이득은 **두 번째 요약 경로(일종의 추가 용량·중간 결합)**에서 온 것이고, 장기 기억의 가치와는 무관하다. 추론 때 상태는 게임 내내 이어지지만, 그 긴 상태를 **활용하도록** 학습된 적이 없다.
- 그래서 (나)로 보이는 신호(이득이 커지는 중)는 ③의 보완이 아니라 추가 경로의 학습이다. 길게 배우면 더 커질 수 있지만 그것도 ③과 무관하다.
- **③이 지금 병목인지는 아무 자료도 말해 주지 않는다.** 64 step = 약 30초, 최대 1분. 1분 넘는 정보가 필요한 결정(정찰로 본 적 테크에 맞춘 빌드, 드랍·공격 타이밍, 상대 병력 위치 추적)의 비율은 이번 자료로 셀 수 없다. 다만 (i) 그중 상당 부분은 AgentMemory(적 건물·적 최대 수·시야 기록)가 이미 관측으로 넣어 주고, (ii) 1·2차 코어 비교에서 기억 길이가 다른 두 코어(LSTM 무제한·GTrXL 64)가 같은 성능이라는 것은 **"지금 단계에서는 64 step 밖 기억이 결정적이지 않다"는 약한 간접 증거**다(LSTM이 긴 기억을 실제로 쓰는지도 확인된 바 없으니 약하다).
- 대전에서 outer·all이 수동적인 것은 가설 수준이다: 덜 학습된 바깥 상태가 토큰·맵·코어 입력 세 곳을 동시에 섭동해 행동이 보수적으로 치우쳤을 수 있다. 또 바깥 LSTM은 게임이 길어질수록 학습 때 본 적 없는 상태(학습은 늘 묶음 시작에서 0부터 최대 64 step)로 들어간다 — **학습·추론 불일치**가 outer 계열에만 있다. 이것이 60분 판에서 유독 수동적인 원인일 수 있다(확신 낮음~중간, 측정 제안 C로 확인 가능).

## 3. 세 약점 밖의 이유 — 대전 결과를 실제로 가르는 것

앞 리포트의 사실을 세 약점에 대응시키면:

| 대전 현상 | 크기 | 관련 약점 | 실제 원인(가설) |
|---|---|---|---|
| T0 상대 패배의 66~80%가 12분 이전 | 패배 651판 중 약 480판 | ① 약간(적 병력 구성), ③ 아님(눈앞의 적) | 초반 러시 방어는 사람 리플레이에서 "스크립트 봇의 러시"와 다른 모습이고, 온도 1 샘플링이 일꾼·건물 배치 결정을 흐리게 함. BC 커버리지 + 샘플링 |
| 무승부 72%가 한쪽 항복 판정 상태 | 리그 632판 | ③ 아님(건물 위치는 기억 엔티티에 있음), ① 아님 | 이긴 쪽이 남은 건물(띄운 건물 포함)을 찾아 부수는 행동이 사람 데이터에 거의 없음. BC 커버리지. 평가 규칙(60분 무승부)이 이것을 전부 무승부로 흡수 |
| 결판 난 판도 중앙 38.6분 | 1,220판 | — | 양쪽 모두 교전·마무리가 느림. 정책의 흐릿함(온도 1) |
| 변형 간 모방 차이 1~3% | — | ①②③ 모두 | 100판·300판 대전으로는 보이지 않는 크기 |

즉 **지금 승패를 가르는 병목은 세 약점이 아니라 (i) 드문 장면의 BC 커버리지, (ii) 온도 1 샘플링의 흐릿함, (iii) 60분 무승부를 정보로 못 바꾸는 평가 규칙**이다(확신 중간~높음). 세 약점은 "일상 행동을 더 잘 흉내 내는가"에는 1~3% 차이를 내지만, 그 차이가 승패로 번역되는 경로가 이 단계에는 없다.

## 4. 가를 수 없는 것과 재는 방법

| 질문 | 측정 | 비용 | 가르는 것 |
|---|---|---|---|
| A. ③ 코어가 실제로 몇 step의 문맥을 쓰나 | 기준 ckpt-10000을 val 500게임에 채점하되 코어 attention 창을 8·16·32·64로 제한(추론 전용 스위치, 코드 소폭) | ROCm 호스트 약 1시간 × 4, 학습 없음 | NLL이 16 step 제한에서 거의 안 변하면 지금 모델은 긴 문맥을 쓰지 않는다 → ③은 현재 병목이 아님. 크게 변하면 더 긴 기억이 가치 있을 가능성 |
| B. ①② 효과가 어떤 장면에 있나 | `bc-eval`이 step별 엔티티 수·행동 종류·게임 분을 함께 내게 하고(코드 소폭), pool·ctx·terrain 대 기준의 NLL을 엔티티 수 구간(<64 / 64~192 / >192)·행동군(교전·이동 / 생산·건설 / 기타)별로 비교 | 추론 약 1시간 × 모델 수(이미 있는 체크포인트), 학습 없음 | pool의 손해가 적은 유닛 장면에 몰리고 많은 유닛 장면에서 이득이면 "요약은 효과 있으나 평균적으로 묻힘". 아울러 "유닛 많은 장면의 비율"과 "교전 결정의 비율"이 처음으로 수치로 나옴 |
| C. outer의 학습·추론 불일치가 수동성의 원인인가 | outer ckpt-10000의 리플레이·결정 기록에서 바깥 상태 노름과 행동 분포(NoOp·공격 비율)를 게임 분에 따라 그림. 또는 추론 때 바깥 상태를 64 step마다 0으로 리셋한 변형으로 T0 100판 | 추론만, CUDA 약 30분~1시간 | 리셋이 성적을 올리면 긴 상태가 해였다 → ③의 바깥 LSTM은 지금 설계로는 쓰지 말 것 |
| D. pool의 "결단력"이 정보인가 분포인가 | pool 대 기준으로 온도 0.7에서 맞대결 100판 + T0 300판 | CUDA 약 2시간 | 온도를 낮춰도 pool이 더 결단력 있으면 요약이 교전 판단에 쓰이는 것, 차이가 사라지면 샘플링 분포 차 |
| E. ③을 제대로 시험 | truncated BPTT 길이를 128 또는 256으로 늘리거나(lanes를 줄여 메모리 유지), 묶음 사이 바깥 상태에 gradient를 이어 주는 학습(메모리 큼) 10,000 update | CUDA 10~12시간(T 128, lanes 16), ROCm 메모리 예산 확인 필요 | 바깥 LSTM이 64 step 밖 정보를 배울 기회를 준 뒤에도 이득이 없으면 ③은 BC 단계의 병목이 아님 |
| F. (가)와 (나)의 분리 | 본학습(S1 한 epoch 39k)의 체크포인트 10k·20k·39k val 채점 + 두 번째 epoch 일부 | 본학습에 포함, 추가 추론 약 3시간 | 39k까지 계속 내려가면 (나), 한 epoch 뒤 둘째 epoch에서 멈추면 (가) |
| G. 대전 병목 확인 | 무승부 10판·초반 패배 10판 리플레이 시청 | GPU 없음, 사람 1~2시간 | 마무리 실패 원인(띄운 건물·병력 방치)과 러시 방어 실패 모습 → 평가 규칙과 RL 보상 설계 근거 |

권장 순서: **G → A → B**(모두 학습 없음, 합쳐 하루)로 "세 약점 중 어느 것이 지금 쓰이는가"를 먼저 보고, 본학습 뒤 F로 길이 효과를 확인한 뒤에 E(③ 재시험)나 pool 재학습을 결정한다.

## 5. 주장별 확신도

| 주장 | 성격 | 확신 |
|---|---|---|
| ctx는 토큰 헤드를 1~3% 좋게 하고 2k부터 안정 | 사실(짝지은 손실·val 일치) | 높음 |
| terrain은 토큰 헤드를 0.5~1% 나쁘게 함, 간격 줄어드는 중 | 사실 | 높음 |
| pool은 행동·delay를 0.6~0.9% 나쁘게 함, 간격 줄어드는 중 | 사실 | 높음 |
| outer의 행동 이득은 −0.5% → −1.8%로 커지는 중 | 사실 | 높음 |
| 이번 학습 방식으로는 바깥 LSTM이 64 step 밖 기억을 배울 수 없다 | 사실(코드·spec 확인) | 높음 |
| outer의 이득은 장기 기억이 아니라 추가 요약 경로에서 온다 | 추론(위 사실의 귀결) | 중간~높음 |
| 개수는 스칼라에 이미 있어 ①의 전제가 약하다 | 사실(030 §4) | 높음 |
| 데이터 부족(가)은 지금 원인이 아니다 | 추론(한 epoch 미만) | 높음 |
| 대전 승패는 초반 생존·마무리에서 갈리고 세 약점과 직접 관련이 없다 | 사실 + 해석 | 중간~높음 |

| outer 계열의 수동성이 학습·추론 불일치 때문이다 | 가설 | 낮음~중간 |
| 64 step 밖 기억이 지금 병목이 아니다 | 간접 증거(LSTM = GTrXL) | 낮음~중간 |
